# 专业判断如何产生

本文件是研发决策规范；以下条件不是已经接入的代码。具体阈值只能来自当前适用的审核规则或已批准课表，不能让模型临时编写。

## 1. 共用输入与推理顺序

输入包括：身份与截至时点、原问题、主次目标、现有计划、当前事实、可比历史、限制、批准规则/候选、未解决冲突。事实必须带单位、来源、时间、修订、实测/估计/计划/预测类别。

顺序：识别问题→核对可用事实→确定适用范围→形成少量候选解释/方案→按限制筛选→用关键事实说明取舍→仅提出所需追问→提出后续观察/版本修订。

任务判定不用题号：
- “多少/算一下”优先计算；“为什么”才需要原因分析；“今天怎么办”需要可执行候选。
- “只问饮食”不强制附训练/HRV；存在直接相关限制时保留。
- “是不是退步”先判断可比表现与时间跨度；不是自动降级用户等级。
- 模糊任务只问会改变选择的分歧，其余可确定部分先答。

禁止单凭关键词静态路由；自然语言任务推断要保留原问题和理由，用户可纠正。对否定、引用、朋友数据和多个日期单独做解析验收。

## 2. 能力与基线

能力档案按维度保存：专项比赛/测试表现、重复训练执行、力量/动作经验、耐受观察、可用条件；每项都有日期、协议、证据和UNKNOWN状态。群体常模、个人常态、目标分别存。

比较过程：
1. 先确定本问题要比较哪个指标及哪些条件。
2. 用截至时点以前、同口径记录形成描述；n是独立观察天/课而非同日采样条数。
3. 显示中心、范围/离散程度、覆盖和上下文；不默认固定5/7/28天即成熟。
4. 今日偏离只是一项事实。测量噪声、可比表现、主观感受和情境变化决定是否值得继续关注。
5. 阶段/设备改变时显式版本化；保留冻结锚点和滚动近期状态，避免长期恶化被平均掉。

能力判断输出“某条件下某表现有证据”，而不是一个万能分数。预测模型另外记录拟合数据、残差、适用距离、外推标记；资料不足不填CS/D′或全距离预测。不能把厂商预测当实测PB。

## 3. 跑步课目的与训练安排

目的来自原计划；不得从组数反推为确定事实。常见目的所需观察如下：

|目的类别|最重要观察|不能直接宣称|
|---|---|---|
|轻松/恢复|实际时长、主观强度、是否符合原定限制|心率低即完成生理恢复|
|节奏/阈值相关|原定区间、执行、组休、情境与可比历史|无测试即确定乳酸阈值|
|速度/加速|计时和起跑协议、每次质量、休息与动作条件|短距离GPS配速等于精确速度|
|专项间歇|分段结构、目标与实际、后段变化、组间恢复|一次训练推算必然比赛成绩|
|技术课|具体技术目标、可用影像/观察、反馈可靠性|单视角画面推出三维关节动力学|

目的达成分三层：计划执行→目标刺激的观察证据→长期适应。单课通常只支持前两层的有限判断。预先设定的判据必须注明“计划约束”或“科学测量阈值”，不能混名。

未来课从适用模板筛选：专项/阶段/经验/目标→日历与资源→已有耐受记录→限制→候选。允许保持现有适用计划，不能为了显示聪明每次改课。缺近期剂量依据时可以提供结构、目的和补项，不输出虚构公斤数或配速。

## 4. 疲劳与响应

不要将指标加权成未经验证的疲劳百分数。分别列：可比表现、主观疲劳/酸痛、睡眠、同源HRV/心率、近期训练与生活负担。不存在的指标不记0，不强迫买表。

分支：
- 来源/协议改变：先限制比较。
- 只有单项偏离、表现与感觉未见一致变化：描述偏离，保留正常波动和情境解释。
- 多项线索与实际表现同向：可以提高“近期负担影响”的关注度，但仍非诊断。
- 数据矛盾：保留矛盾，并挑最能区分的下一观察。
- 已有疼痛/医疗限制：独立约束候选，不靠综合分抵消。

个人响应采用自然训练过程中的可比观察。记录暴露、响应时点、可能混杂和反例；新证据可增加支持、削弱或保持未知。不可为了验证假设主动让用户睡眠不足、挨饿或带痛训练。

## 5. 力量、跑力与短时安排

力量模板必须完整：目标、动作版本、适用经验、组次/持续时间、负荷口径、组间休息、执行提示、停止/替代条件、进阶条件、允许调整变量和审核来源。

进阶候选不靠吨位：核对动作版本/ROM、实际完成、休息、主观强度及质量；在原批准进阶规则内提议一个变量。RIR/RPE是报告数据，不把新手估计当精密测量。

跨日协调保留各领域量纲：跑步高速暴露、力量局部负担、爆发动作质量、总时间与生活限制。不能把kg·次与公里直接相加。形成“有证据冲突/条件未知/未发现已知冲突”，而不是未知即安全。

候选必须说明：保护哪节关键课、保留什么、减少/延期什么、可能代价和复查条件。同日分开属于可选安排，研究中的分组时距不能直接成为个人硬性恢复时长。

热身选择先问整课还是热身时长。5/15/30–40分钟是用户时间选项，不是已证实生理档位；从适用审核模板选择，短时方案不能删除关键准备后仍保证高强度安全。

## 6. 营养与体重

先检查记录覆盖，再考虑需求。缺份量/配方时用可确认候选；外卖不能仅凭菜名输出精确营养。过敏、饮食限制、预算和烹饪条件参与替换。

能量估计选择一种口径清楚的方法，记录已含哪些活动。体重变化用相似测量条件和趋势，不能单日换算脂肪增减。真实需求与估计的差异通过持续观察修订，不以一天差额硬扣食量。

按目标分支：
- 运动表现：围绕课的时间、性质和恢复间隔安排食物；不默认减重。
- 增肌：训练刺激、能量与蛋白、执行条件共同考虑；不把高蛋白等同肌肉必增。
- 控重：先了解实际趋势与可执行饮食；与赛期/健康限制冲突时明确取舍，不自动放大赤字。
- 只问一餐：只处理该餐及相关影响，不强制开全周计划。

数值参考在reference-ranges.json；只有条件匹配、来源明确、体重有效、适用人群确认后才可作教育性换算，仍不自动成为个体目标。临床情境转专业人员，不用软件“REDs评分”代替诊断。

## 7. 知识、证据和输出

检索顺序：明确知识缺口→筛选人群/项目/结局→查实际可访问段落→区分原结论和App设计推论→注明适用/排除条件→纳入候选。没有出处的数值不进入执行规则；来源冲突先查情境，不凭权威大小或时间简单覆盖。

最终用户输出：先直接回答→最多几个关键事实→一个当前重点→可选的具体下一步→必要的不确定性。详细出处和公式可展开。合成教学例用于风格与逻辑训练，不作为验收答案泄漏给模型。
