# R185 本地训练存储迁移方案（未执行迁移）

本轮保留现有 localStorage envelope、事件日志和更正记录。已有设备原始证据继续使用现有 IndexedDB；不新建第二套训练事实层。首次确认保存训练后显示持久存储状态与申请按钮，只有用户点击才调用 `navigator.storage.persist()`；不承诺浏览器一定批准或能抵抗主动清除。

后续迁移按以下顺序实施，所有步骤均在本机进行：

1. 导出带版本、运动员 ID、记录数量及 SHA-256 的完整备份。纳入训练事实、导入、正式计划、计划候选、画像、历史假设、更正、对话状态及现有设备证据。未知版本停止迁移，不丢弃字段。
2. 使用现有 storage 接口增加 IndexedDB 后端。保留键名和 envelope 结构；采用事务写入临时版本库，写入迁移台账。任何失败保留旧库为唯一读取来源。
3. 以运动员和稳定记录 ID 幂等复制；事件与更正按追加顺序保留，缺失不补零，VOID/RESTORE 不删除原事实。避免只复制当前投影而丢掉历史。
4. 比较旧新内容摘要、逐类数量和来源依赖；核对可见时间、同协议历史、原计划与候选隔离。完成一致性核对后原子切换读取标志，再开放写入。切换期间串行存储写入，避免多标签页丢更新。
5. 遇到配额、权限、浏览器中断或未知模式时回到旧版本，不删除临时库或旧备份；台账支持重试。后续新写入也必须有可导出的追加日志，以便回退时重放，不能简单切回旧快照丢失新训练。
6. 旧 localStorage 不自动清理。经迁移专项测试及用户确认备份后再单独提供清理操作。浏览器清除网站数据可能同时清除两种存储，因此备份下载仍需保留。

待执行专项验收：空库/旧版本/损坏 envelope/多运动员/多标签写入/中断续传/配额耗尽/事务失败/更正链/作废恢复/刷新与进程重启/离线/导出还原。R185 未宣称这些迁移测试通过。
