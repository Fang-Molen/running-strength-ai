# 方坤新题测试：执行说明

本包为 **16 组新公开开发题、32 条标准/单事实对照路径**，另有一份 245 条合成历史数据及 3 个 token 测试问题。只完成题目、评分参考和数据的结构/算术校验，尚未运行方坤或 DeepSeek。它用于开发回归与发现问题，**不是独立隐藏题或专业认证**：题目及答案都可能被开发者看到。

## 用户授权与测试环境

用户已授权 Codex 为本项目的模拟测试使用其 DeepSeek API，允许发生测试费用，旧交接里禁止付费调用的限制对本次合成测试不适用。运行环境如已配置密钥直接使用；不在日志、源码或交接包中输出密钥。只用本包含的合成资料、隔离身份与隔离存储；不访问真实健康/训练数据，不修改正式计划、不部署。若模型、密钥或网络不可用，先执行不依赖它的验证，记录真实失败，不能把假模型当成实测通过。

## 本包结构

- `01_方坤输入_32路径.jsonl`：逐行读入的题面；仅包含用户消息，不含参考答案。
- `02_评测参考_勿传方坤.jsonl`：评分参考，永不放入待测方坤/DeepSeek 的 system prompt 或用户消息。
- `03_合成历史_245条.jsonl`：240 条旧跑步、4 条近期本人事实和 1 条其他人事实；严格身份隔离。
- `04_评测与token测试.md`：所有三个历史问题的参考值、Token A/B 方法与评分细则；不发给待测模型。
- `05_校验报告.txt`：数据结构、算术与校验输出；不是运行方坤的结果。

## 运行16组题

1. 以每个 path_id 为一个隔离会话，共 32 个会话；A 和 B 分开，逐条发送 `messages` 中的 user 内容，不向系统提前提供后续消息。Q11 有两轮，其余单轮，因此**每个版本基础运行应有 34 轮**；成功API请求数按实际记录，额外追问、重试和失败另计。
2. 从现有 App 用户入口、联网状态、上下文构造、HTTP 控制器到模型执行，不用“直接把题发给模型”的结果冒充 App 端到端。题面事实作为用户自述处理，不能称已经写入训练记录。完整会话回答、请求中实际收到的资料、状态和证据分别留存；如果无法取到请求明细，标“模型是否收到资料未验”。
3. A/B 只改变参考表 `changed_field` 描述的一项，预期差异和应保持不变的项目需核对。Q10 属于**无关事实变化不应改变结果**，其余可能需要答案变化，不能以差异或相同本身自动判正确。
4. 优化前版本可用则两版同模型/参数/问法、同隔离条件配对；优化前不可用则独立报告候选，不计算提升。A/B 顺序预先确定或随机化并记录；只对关键边界题做适量重复，重复是同题重试，不算新独立题。
5. 人工先根据 `02` 核对每轮数值和回答含义，再根据 `04` 打分。Q11 的两轮分别记录；不只判断最后一句。输出/拒答/失败/超时/未运行均留档。

## 长历史 token 测试

请先将 `03` 通过测试专用适配器写进**隔离**事实库：SYN-A、SYN-B 独立；如果当前产品尚无可用导入适配器，报告阻塞，不得将 JSON 手贴到用户问题后冒称真实数据库检索通过。记录导入的行数、去重、数据映射、时区、状态、版本、导入回执和失败。

三道问题、参考值与比较要求见 `04`。每道分别运行“全量历史对照”和“按需检索/摘要”两种模式，各一个独立会话；为运行这项测试，可在隔离的测试适配器显式建立全量对照，最多只发 SYN-A 的 244 条记录，任何模式都不发 SYN-B 私人事实。真实 App 旧版本作为对照时注明；如果只能新建测试适配器，则称“测试模式对照”，不能冒称旧版实测。

两种模式保持相同账户、as-of、问题、数据、模型、参数、system指令和回答长度设置；只改变历史提供方式。对三个问题记录按需检索与全量对照分别给到模型的消息/hash、事实 ID、缺失、反证与摘要，比较响应质量；对于消息内容按字段脱敏保留以防敏感信息写入日志。请求中个人身份只使用合成 SYN-A。数据包上游来源须与引用一致。每条消息、重查与重试都记录，不能只取首次调用的 token。

先做离线数据准备与假模型 HTTP 检查，再调用真实 DeepSeek；测试若中途中断，则已运行和未运行路径分别计数。按 `04` 记录所有调用的 token、可用usage、请求数、延迟和费用；API 未提供时填未知，不按字符数冒充 token。输出包括每题结果和总体对照，不用测试结果宣称疲劳预测医疗有效。
