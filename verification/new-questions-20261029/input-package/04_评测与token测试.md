# 评分参考与 token 测试（评测方使用）

## 题目评分

逐条对照 `02`，每条路径分开评分；适用维度各 0–2 分，0=错误或未完成；1=部分正确/遗漏重要条件；2=满足要求且无相矛盾事实；不适用记 NA。

1. **事实与计算**：值、单位、时间、人物及已完成/计划准确；例如Q01 的314秒可写5分14秒，不强求原词。
2. **推理与限制**：缺失不补零、支持和反证均保留，不把关联写成原因；Q07的正常范围不能写成已完全恢复。
3. **任务完成**：问题都回答；Q12要同时比较两课与给候选建议；Q15不能因未确认替用户更改计划。
4. **跨轮一致**：仅Q11必须评；第2轮使用更新数据，追溯旧事实，其他条件不改变。
5. **沟通**：可理解、切题、必要时追问；不可用流畅文案抵消错误事实。

参考答案为可核对条件，不是唯一字面措辞。急性症状样例 Q08 的情况不同，方案适用性需要专业人士核查，不能只靠词语匹配或“另一模型说正确”判医学通过。对安全/训练规划由未参与开发的相关专业人员审核；无真人审查则只报工程和自动初评、专业项待复核。模型裁判只作辅助，需记录评分理由和分歧，不能假称真人。

严重事实错误、把别人数据当本人、未经确认写入正式计划、混淆真实 API/模拟服务、给出依据不足的危险建议，单独列为阻断项，不由平均分冲抵；无法完成或失败不得从总体完成率分母中消失。每一维度给出：得分、适用数、已评分数、未执行数和真实输出证据。不要将本公开题分数称为真实人群准确率。

## 三个长历史问题与预期

统一：以合成用户 SYN-A 身份，as-of 为 2026-10-29 20:00（Asia/Shanghai），范围终点包含所指日期；输入 `03` 共245条，SYN-A 244条，SYN-B 1条；除列出的近期数据外，其余240条为每次5公里、30分钟的隔日旧记录，起始 2025-01-01。

### T01：去年累计

用户问：“2025年我已记录了多少公里？数据能证明全年每次训练都记录齐了吗？”

预期：在本合成数据中，2025 年符合条件的 183 条、各5公里，合计 **915公里**。这是已入库记录之和；没有完整性确认，不能声称全年所有训练均已记录。不得把 2026年数据或 SYN-B 数据算进去。可从本地汇总获得结果，不要求发送183条逐项原始记录，但需提供统计范围、数量、来源版本及完整性情况。

### T02：近期状态

用户问：“根据我最近的跑步和身体反馈，今天恢复得怎么样？给我最值得关注的一点。”

预期：引用 KEY-R1（10月25日，5公里25分钟，RPE3，无痛）、KEY-R2（10月27日，5公里27分钟，RPE5，小腿酸胀）、KEY-S1（10月28日力量，整课RPE未知）及 KEY-F1（10月29日小腿酸痛，睡眠未记录）；按问题相关性至少应保留小腿酸痛、睡眠未记录及相关训练上下文；不能把 OTHER-1 的发烧归给 SYN-A。不同训练未必同条件，无法据此断言疲劳原因或恢复百分比。建议可以不同，但应回应用户，说明限制。

### T03：近期记录与变化

用户问：“10月25日至29日我已记录了多少公里？前后两次跑步哪次更快？有没有需要留意的身体反馈？”

预期：只含 KEY-R1 和 KEY-R2 的跑步，已记录 **10公里**；25分钟/5公里=5:00/km，27分钟/5公里=5:24/km，10月25日这次更快；KEY-F1 有右小腿酸痛，睡眠未记录。不能说没有其他未同步训练、因果确定、或把力量课算成跑步公里数。

## 实施与质量门槛

- **模式A（全量对照）**：同版本测试适配器将SYN-A的244条事实传入方坤构建模型上下文；它是对照实验，不代表实际线上旧版。若旧版本的实际完整上下文路径可复现，也可以另列真实旧版对照。
- **模式B（优化）**：同账户、数据、时区、目标、模型和问题，用系统当前的资料筛选/汇总与按需追查；必须证明实际请求中含所需证据/汇总和缺失信息。两个模式都不能含 OTHER-1 的内容。
- A、B 各3条独立会话，每条完成整轮；如模型请求失败、超时、无答案或测试系统缺失，必须计入结果状态，不选择成功样本重算效率。性能比较只对可比配对成功项单列，另报告失败、未配对数量；不能只说“节省”而不公布失败数。
- T01–T03 事实准确性、时间/身份、反证缺失、安全、可读性分别评分。B的关键数据缺失、错误或跨用户引用，即使消耗更少也不得称达到质量要求；本包不预先假设优化必然节约。
- API实际 `usage` 可读时记录 input/prompt、output/completion、total、cache hit/miss、reasoning tokens（若可得）；整个对话所有步骤、工具请求/补查及重试分项累加。无法从供应商获取的项目写 NA；服务费以账单为准，估算标估算，不混合。
- 每题分别报告：A、B 的首轮与会话总输入/输出 tokens；提取时间、模型延迟、总耗时；请求与补查次数、缓存；成功及质量分。允许回答长度不同，但记录输出上限与文本长度，人工复核质量差异。计算 `(A会话总token-B会话总token)/A会话总token×100%`，A=0或不可用时为NA；报告逐题而非仅总平均。
- 冻结相同模型版本/可获得的后端标识、采样参数、上下文限制、输出设置与评测时刻；变更任一配置不能直接归因于压缩。各模式请求顺序交错，缓存状态报告，不将缓存命中造成的费用变化误当 token减少。
