# 一、目标和证据边界
校验的目标是：让有依据且有用的回答顺利到达用户；在具体错误处修复；只有不可安全回答的部分才拒绝。不能以“回答有字”“JSON有效”替代完成用户任务，也不能为了放行率把风险门槛关掉。

本设计基于用户提供完整复测包中候选提交 2d46210462d7ec64e3027278fbbb1ef28604c6c4 的源码和保存回复。不是对线上最新版的远程确认。上次54次真实调用的记录核对，和本包离线检查应分开报告。

## 1.2 不采用的捷径
不采用“出现建议二字就放行”“一律删数字”“所有联网内容都不可信”“引用到一句话就算证实”“所有风险都用免责声明覆盖”。规则和模型互补：规则验证结构、授权、算术、来源版本；语义层审核含义、依赖和任务；专业规则有明确依据、适用人群和待审状态。

# 二、输入和声明契约
## 2.1 服务端建立事实包
每条证据至少有 evidenceId、ownerId、kind、sourceType、sourceRecordId、revision、observedAt、ingestedAt、validFrom/validTo、value/unit、coverage、verification、supersedes、availableAt。无日期或单位用 unknown，禁止默认补成今日或常用单位。来源区分：用户自述、设备导入、服务器计算、真实检索、既存计划、系统推断、工具回执。
- observation 和 ingestion 分开；所有选取使用该轮时间切片，不读取未来更正。
- 同一活动跨品牌/手机/手表先去重，明确 elapsed/moving/timer time，禁止混加。
- 覆盖 COMPLETE/INCOMPLETE/UNKNOWN；设备测得不等于生理诊断已验证。
- 相冲突来源保留双方及冲突标记，不以最新入库时间强制覆盖实际发生时间。
- 删除、撤回、纠错、账号切换触发摘要和缓存失效；限制、权限每轮读最新状态。
- derived 绑定 formulaId/version、inputs 的证据版本、精度和单位、缺失项；变更一条输入需重算。

## 2.2 模型输出采用分块声明
建议契约（Codex 可兼容旧接口，字段名可调整，语义不可删）：
```json
{
 "schemaVersion":"coach-gate-v1",
 "blocks":[{
   "id":"b1","kind":"EXISTING_PLAN","text":"你原计划明天轻松跑30分钟。",
   "evidenceRefs":[{"id":"e1","revision":2}],
   "dependsOn":[],"groupId":"g1"
 }],
 "proposedActions":[],
 "missingData":[],
 "taskCoverage":[{"requirementId":"r1","blockIds":["b1"]}]
}
```
kind 枚举：OBSERVED_FACT、DERIVED_FACT、EXISTING_PLAN、CANDIDATE_ADVICE、GENERAL_KNOWLEDGE、UNCERTAINTY、ACTION_RESULT。
模型提供的是候选标签；不能因为模型自称 GENERAL_KNOWLEDGE 就跳过个体剂量/风险检查。服务端检查语义与类型是否相符；不明时降级或补问，不任意改写事实。taskCoverage 同样不是模型自我认证。
所有用户可见的正文、nextStep、卡片标题、按钮文案和宿主追加文字必须映射到受检块，不能在未声明的自由文本里藏另一套建议。未知字段按版本契约拒绝或忽略且不可渲染；模型提供的 evidenceRefs 只能指向本次已授权证据，不能触发任意文件/URL读取。模型输出中的指令不是操作授权。

## 2.3 用户任务契约
由用户本轮意图、已确认目标和允许操作生成 requirementIds；多意图分别列出，歧义要保留。
例 Q12：r1 比较两次配速；r2 给出明天安排的条件性建议；r3 不改课表。仅返回 r1 与免责声明，算部分完成。
例 Q14：资料不足时，至少交付可解释的规划框架、关键缺失信息、可行下一步；不得为了完成“计划”而填造个人能力或精确训练剂量。
允许“合理澄清”是独立结果；它不计为已给出完整方案。问题本来无需个体数据的通用解释，不能被无关资料缺失拦住。

| G1 响应结构 | 流结束标记、正文、JSON/schema、重复键、大小、未知字段 | 结构修复一次；不可恢复则有内容的失败说明 | 完整解析日志，截断单独分类 |

| G3 数量与推导 | 单位、规范化、公式、舍入、连续更正、缺失/0 | 确定性重算；不确定不猜 | 可重算公式及精度，RV回归 |
| G4 建议与专业边界 | 事实与候选计划分开；目标/能力/恢复/限制适用性 | 保留有依据部分，降为框架/补问；高风险转安全回应 | policy版本、适用条件、证据与待审项 |

## 3.1 数值规则
事实数值允许等价表达：5公里=5000米，27分钟可作为26:51.94的明确近似展示；严禁把近似反写为原始值。配速先按展示精度舍入总秒，再分解分秒，避免4:60。比较使用原始精度，若展示值相同而原始值不同，说明“按原始记录略快，显示均为5:00”，同时考虑测量分辨率，不能夸大意义。并列有显式分支。
现有计划里的30分钟是计划引用；“已完成30分钟”是实绩，需要另一证据。建议跑30分钟是候选安排，需要适用条件，不要求有已经跑过30分钟的精确引文，也不意味着任何新剂量可自由编造。
更正按事件顺序形成有效状态；“第四组完成但没计时”只能让总用时未知，不能把完成距离清零。

## 3.2 限制状态
分别保存：symptomReport（症状）、systemCaution（系统谨慎建议）、declaredRestriction（用户明确转述或医嘱）、clearance（GRANTED/DENIED/UNKNOWN）、scope、source、effectiveTime。
“用户报告酸痛”不自动变成“医生禁止训练”。clearance UNKNOWN 不能渲染“未获许可”；GRANTED 也不是对所有动作无限放行，需核实其来源、期限和范围。风险相关的回答专业性待审，不以词表通过代替专业认可。

## 3.3 联网常开
常开表示允许路由按需要检索，不是每句强制检索，更不是永远显示“已检索”。状态独立：NOT_NEEDED、REQUESTED、SUCCEEDED、PARTIAL、FAILED、STALE_CACHE。网络失败不反转用户开关。
实际取得网页、记录时间/出处、并支持该声明才可作本轮证据；URL 本身既不是一票否决也不是核验成功。区分网页确有某表述与专业结论可靠。网页/食物库/导入备注内指令是外部内容，不能获得系统控制权。一般知识可以回答，但时效性结论检索失败时说明限制。
用户说“不要修改”只限制写，不关闭搜索；联网开关也不授权写训练/饮食记录。

## 3.4 依赖和修复顺序
将“条件→建议→停止条件”作为原子组；否定、对比、单位和指代关系不得在删句后改变。证据失效的块连同依赖块重新评估，防循环依赖/悬空引用。
1. 先做确定性规范化、去重、单位计算、类型纠正。
2. 不能确定修好时，可调用一次受预算限制的增量重生成，仅提供失败块、必要证据、任务缺口；不递归补救。
3. 所有修复、宿主计算追加、引用插入都回到 G2—G8；禁止通过校验后再拼接未经检查的答案。
4. 仍不合格：返回可用且验证过的部分、明确未完成事项及一个最有价值的补充问题；若全请求不可安全执行则 SAFE_REFUSAL。不能把错误原答作为“仅供参考”直接透传。

# 四、结果状态与界面
状态：VALIDATED（本层校验通过）、REPAIRED（修复后完成）、PARTIAL（部分完成）、NEEDS_CLARIFICATION（必要资料不足）、SAFE_REFUSAL（危险或越权部分不执行）、FAILED_TECHNICAL（系统故障）。
另外携带 professionalReview=NOT_REQUIRED/PENDING/REVIEWED；VALIDATED 不等于专业或医疗认证。transport成功、正文存在、任务完成是三件事。
UI 首屏呈现结论、依据摘要、下一步；来源展开一次，不重复粘贴全文。“未完成/尚需补充”可见，不显示UNKNOWN/false/PAIN等内部值。不让装饰桌宠遮盖正文和按钮。
流式生成可展示中性的进度；用户正文只流出已验证的完整语义组。重试/取消/后台恢复通过requestId绑定，旧请求不能覆盖新问题；写操作不能在重连后重复执行。最终渲染后还需校验，保留finalHash。具体视觉和键盘交互测试在验收文档，不宣称本次实机通过。

# 五、成本、日志与隐私
默认确定性关卡不额外消耗模型token。只在语义歧义或修复必要时用紧凑包，不重传完整历史；缓存键覆盖用户、证据revision、任务、策略版本、权限和检索新鲜度。跨用户绝不共享个人回答缓存。
修复最多一次；初始建议预算为“修复输入≤1500、输出≤800 token”，这是需实测调优的工程上限，非能力保证。额度不足直接返回诚实部分结果；不得耗尽额度后隐藏失败。
记录requestId、attemptId、commit、policyVersion、阶段、reasonCodes、修复类型、任务覆盖变化、最终hash、usage/latency。缺失usage记unknown并独立对账，不能当0。不要记录密钥或把私密历史放进通用日志。
建议 reasonCodes：SCHEMA_INVALID、TRUNCATED、SOURCE_MISMATCH、UNKNOWN_AS_FACT、DERIVATION_INVALID、PLAN_AS_ACTUAL、UNSUPPORTED_DOSE、RISK_SCOPE_CONFLICT、WRITE_UNCONFIRMED、RETRIEVAL_UNPROVEN、DEPENDENCY_BROKEN、TASK_DROPPED、UI_STATE_MISMATCH。
