## 每项的验收动作
1. 修改前重放旧失败，保存 raw→旧final→新final；已公开案例是回归，不能宣称盲测。
2. 对规则写正反例，不仅验证“不该放过”，也验证“应正常回答”。禁止只按Q编号分支。
3. 先纯函数、再控制器、再端到端；把模型输出可用性和后处理损伤分开计数。
4. source test fixtures 不能读未来轮答案；测试集 expected 文件不得进入模型prompt。
5. 使用现有保存回复验证过滤层，只能证明下游行为。若改了输入事实语义，旧模型回复回放不足以证明新模型理解，另做已冻结版本的必要真实测试。
6. 用户曾允许 DeepSeek API 测试，但旧交接显示额度已耗尽。核实当前允许额度/限额后再运行；没有预算不得暗中付费。本包默认离线模式，不含调用外网的脚本。
7. 现有项目 lint/typecheck/相关测试按项目说明执行；未执行必须写原因，不能填PASS。
8. UI测试见03；额外检查同一活动摘要、关联卡片、手表详情统一口径，引用该活动时不把手机与手表时长相加。这个数据源问题若超出本轮改动范围要单列缺陷。
