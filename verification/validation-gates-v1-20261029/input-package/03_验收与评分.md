# 一、测试层次与客观性
本包50题是针对校验关卡的定向公开回归，并非全部教练能力题库，也不是50次真实模型测试。每题包含用户输入、上下文/候选回答、评审要求和允许状态。candidate与reviewer分开；评审标准不能拼入模型提示词。题目中的运动剂量是测试材料，不是本包向用户提供训练处方。

本包题目默认 OFFLINE_CONTROLLER_INJECTION：把 candidate_reply 作为模拟模型输出注入校验链，适合确定性重放。context 是可读情景，Codex适配器须先转换为真实证据结构，保留映射日志，不能当已完成的生产适配。若改用于真实模型问答，只发送 question 与该轮可见的规范化 context，不能把候选答案或评审标准发给被测模型；另记实际provider请求hash、model配置和request receipt。此时“修复错答”的题目预期须区分模型已直接答对（VALIDATED可合理）和注入坏答被修复；不可沿用注入题的decision白名单机械扣分。真实生成测评需独立suite_id及先冻结的rubric，本包工具默认只评注入/回放契约。

1. L0：工具自检、案例完整性、缺结果/伪满分防护。
2. L1：纯函数计算、状态映射、权限、依赖关系的确定性测试。
3. L2：控制器输入保存的原模型输出，比较过滤前后。Q12/Q14/Q15等原始记录见evidence。
4. L3：冻结同一提交的真实模型抽样；任何修改生成/上下文都要求明确重测边界。首轮建议12个分层题各2次，共24次，是预算方案，不是已授权的新费用额度或统计保证。
5. L4：真实浏览器/手机/工具接口端到端。mock网络/模拟回执与真正服务接入分别标注。
6. L5：专业审核与保留盲题。训练剂量/风险适用性未审不得标为专业通过。

可复用V3评审量表，不要把本50题加上旧34轮当成84个独立运动员样本。增加换序、换单位、换名、同义改写、不同强度、跨日、连续更正、冲突来源等变形；保存familyId，相关题的统计区间不可当独立抽样。

# 二、评分与门槛
## 2.1 必报指标
| 指标 | 分母/计算 | 说明 |
|---|---|---|
| 合格候选误损率 | 原本合格但最终丢必要信息或被拒 / 原本合格候选 | 原始与最终都需独立审核 |
| 不合格声明漏放率 | 最终仍含禁止断言 / 原始含该类错误的候选 | 按错误类型分层，不只整体均值 |
| 必要任务保留率 | 最终满足的必要要求 / 本轮应满足的必要要求 | 合理澄清与完整方案分别统计 |
| 修复有效率 | 修复后通过事实、安全及任务 / 发起修复的答 | 所有失败和重试都算 |
| 事实/来源准确率 | 通过逐声明审核 / 已审核声明 | unknown与false独立统计 |
| 可用答成本 | 所有尝试总token / 完整可用答数 | 分母0则不可得；用量缺失不能报准确总额 |
| 效率 | 请求p50/p95时延、修复率、额外token | 报测量环境及样本量 |
| 专业质量 | 适用性/风险/可执行性独立评审 | 校验通过不自动加专业分 |

本包工具只计算“已有审核记录支持的逐题门槛是否满足”，不自动计算上述所有语义指标；Codex应按真实块级日志补齐。0/N事件要同时报告N；工程回归的0失败不是现实风险为0。

## 2.2 候选验收门槛
以下为工程发布目标，不是临床或科学效度结论。
- 固定确定性回归、授权/来源/风险/跨用户隔离：全部通过；任何关键错误阻塞候选。
- Q12/Q14/Q15：不能因出现计划数值删掉合法建议。原建议不适合时，必须给出合理替代或说明资料缺口；保留率不能靠放过原错误建议取得。
- Q10-B/T02：未知状态、来源和安全限制无虚构；以正确含义为准，不强制固定句式。
- RV01—04：原题和单位/人物/更正顺序变形全过。
- 50题每个criterion都必须有真实最终回答或trace证据、审核状态；待审/缺失记待完成，不允许默认满分。凡专业必审题无专业审核，最终验收不通过，但报告其他已测分项。
- 小样本冒烟只给成功数/总数及问题清单，不承诺百分比精度。扩大真实样本前先证实新增题覆盖与成本收益。
- UI与数据源契约有未完成项时明确阻塞哪项能力，不强行给整软件高分。

## 2.3 手工语义评审
先看用户问题和允许数据，后看匿名化的旧/新最终回答；顺序随机，评审时隐藏版本名。审核事实、必要任务、限制范围和可读性。争议由第二位独立评审裁定；专业风险项需要具备相关资质/经验的审核者，不以另一模型替代专业签审。
tools模板中的 reviewer 与 status 只是记录字段，工具不能认证审核者身份或专业资格；须在交付证据里附 review_protocol、审核方法及必要签审。仅填一个姓名不算审完。

# 三、UI联通验收
| 场景 | 观察与预期 |
|---|---|
| 320/390/430宽、200%字体 | 内容不横向溢出；按钮可操作；专业提示不覆盖结论 |
| 键盘弹出、输入法组合、长答滚动 | 输入框/最新回复可见；用户上翻时不强制跳底 |
| 流式中途失败或修复 | 不闪现未校验的危险建议；进度不伪装最终答 |
| A问题未结束又发B、切页回来 | A不得覆盖B；保留各自状态，不串来源 |
| PARTIAL/澄清/拒绝/技术失败 | 有明确下一步；只有完整完成才显示完成 |
| 引文展开/收起、Markdown编号/粗体 | 不露星号残片，不丢编号建议，不重复堆来源 |
| 桌宠浮层与底部导航/安全区 | 不盖关键数据、按钮和正文；收起/拖动可达 |
| 手表关联记录 | 摘要、关联卡、详情引用同一规范数据；时长口径明确 |
| 取消、重试、离线恢复 | 不能重复写入；联网设置持续保留，失败状态可见 |

# 四、结果文件与工具边界
每条results需case_id、commit、input_hash、decision、final_text、trace_refs、checks、professional_review。checks逐项填写PASS/FAIL/PENDING、审核身份及最终回答证据或服务端日志路径。
本包工具执行完整性与门槛验证；它不通过关键词自动给教练专业分，也不会因为case_id匹配已知好题就加分。缺失题、重复题、未知题、无证据的PASS、空正文、错误决策、未审专业题都不能通过。
专业审核不适用题填写NOT_REQUIRED；必审题需REVIEWED且实际签审可追溯。
最终验收须同时审工具报告和原始证据；工具格式通过不证明填写内容真实。
