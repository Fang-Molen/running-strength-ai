# Review scope and identity

The primary Codex agent read all 50 questions, normalized evidence, resulting controller output and the 150 frozen rubric criteria. `review-engineering.py` serializes that explicit initial engineering inspection; it does not infer PASS by keyword and does not send candidate/rubric content to a model. PASS means evidence within the named synthetic fixture supports that engineering criterion. It is not an independent blinded semantic review, expert sign-off, live-model generation result or production tool/device integration result.

A separate AI code reviewer inspected commit d1a0789 read-only and supplied seven counterexamples. All seven were reproduced and repaired, with original RED/GREEN logs. This review covered source boundaries, task coverage, source labels, arithmetic and retrieval clocks/client delivery. It did not review all final 50 outputs, medical appropriateness, later UI/tool fixture changes or the complete repository. No human or medical expert participated.

No reviewer identity or qualification is fabricated. The seven rubric-required professional reviews remain PENDING. Abstract public fixtures G032/G034, real retrieval, registration persistence/reconciliation, card/detail wearable consistency and an actual sleep resync control remain unestablished where explicitly marked. Independent quality metrics are null, not zero-risk or 100%.

The original ZIP, 50 questions, rubric, calculators and input manifest are frozen. Adapters instantiate scenario narratives as synthetic canonical records, and log those mappings, original hashes and final input hashes. Test-case IDs occur only in fixtures, never in production decision logic. G037/G038 use read-only fake receipts, never execute a food registration. G039 revokes actual synthetic SQL authorization before controller dispatch. G048 includes a real browser concurrency/cancel/reconnect check with synthetic backends. Development hot-reload messages are suppressed and retained in browser logs so frozen-source observations are stable; service-worker and physical-device behavior are not established by that fixture.

`gate_eval.py` is the supplied, unchanged record-contract checker. Its report is not an automatic semantic judgment or software release certification. Full acceptance stays blocked even when a controller decision is in the allowed list.
