# 方坤 R5 交付与验证

日期：2026-10-25。基线为实时 GitHub `master` `06539ca29e6c88f4c235c3a40851b7b97c5e7c52`；交付前再次核对主线未移动。865b032 的有效 R4 内容已在主线，不用旧包覆盖。PR #1 已核对，仅保留原文档任务。本轮代码在 `codex/r5-integrated-coach-20261025`，通过独立草稿 PR 交付，不合并、不部署，没有调用付费模型。

## 实现范围

### 对话修改资料与训练

- 在原方坤对话增加确定性意图识别、当前事实读取、变更预览、显式确认/拒绝、写入、撤销和版本历史。模型没有写入端口。
- 体重区分当前测量、目标和指定日期更正；历史更正按测量日期排序，不会伪装成最新当前体重。年龄、身高、训练日、器材、身体限制和备注使用各字段来源与保存时间。
- 已保存的结构化跑步课可替换为轻松跑，力量课可逐动作减少一组；组合课保留两种项目。轻松跑的纯跑时间不超过原结构，显示时长同步变化，不把间歇整课时长当纯跑剂量。
- 执行前核对身份、资料、症状、日历及版本；复用原日历写入锁与原子回执。重复提交、过期草案、后续修改和已经开始的训练均有保护。补偿撤销保留原始事实与审计历史。
- 当前消息中的疼痛或危险症状先评估，不会被体重或改课意图抢先拦截。资料写入后通知健康、饮食、训练与教练共享读取层。

### 疼痛、酸痛与局部症状

- 健康首页和独立身体记录页接入症状面板；记录部位、侧别、程度、持续时间、诱发动作、功能影响、变化和训练引用，保存追加式修订及撤回历史。
- 按 3/7/14 天显示观测和变化；缺失天数保留未知，疼痛与酸痛分开，肌群刺激不转换成组织恢复率。
- 症状投影进入已有健康分析与安全评估。加重/功能受限优先于设备恢复分数；后续一次零值不自动解除 R5 已有安全限制。只提出候选安排，不诊断伤病。
- 睡眠、主观反应、实际跑步与力量暴露作为并列证据，不宣称观察关联证明了伤病原因。

### 每周复盘与下周草案

- 复用原事实投影、逐段/逐组计算、肌群暴露和建议反馈；区分实际完成、部分完成、漏练、跳过、未记录和未来课程。
- 恢复指标按提供商、账号引用、设备、协议和单位分组；主观恢复与症状独立列示。饮食仅统计已记录的已知小计，全天摄入、缺口和缺项不推断。
- 记录两种竞争解释、支持、反证、待核对信息和区分方式；仅复用已核对适用条件的 R4 科学参考，保留来源、人群与限制。无法匹配时明确说明，而非补造依据。
- 草案为具体已保存课程的副本/差异，参考目标、训练日、原安排、近期实际剂量、安全限制、已记录比赛日期和相邻关键课。时长、跑量、组数、强度逐项受实际上限约束；未知关键剂量时只预览，不能确认执行。这是产品保护规则，不是个人耐受已被验证。
- 确认后原子写入，撤销复原，不叠加原 V4 同日课程。原始自由文本 V4 继续保留；不能从标题虚构可执行参数。
- 周日、下次打开、回到前台或应用内按需生成；没有服务端定时任务或后台推送。更正、撤销、设备或新反馈导致依据变化时旧草案失效，追加修订并保留历史。修复了同一时间戳下旧复盘遮住新修订的问题。

### 扩展合同及回答边界

`contracts.ts` 预留比赛周期、实测能力指标及饮食训练联动合同，包括测量日期、来源、方法、可信度、实际引用和无写入权限。未完整开发三个扩展方向。R4 跑步/力量候选取并集，避免力量分支遮掉跑步。

联网继续使用现有接口与鉴权。返回前检查当前作用域和事实版本，再复用现有数值/单位/来源/安全审核；含数值的自由文本必须绑定到宿主确认的完整事实句，否则回退。离线分析不调用模型。输入和呈现回答维持 1000 字上限，未知不补造，最多两个关键追问。年龄记录不收窄原范围；精确公式适用性仍独立判断。

## 限制、评价与回滚

**工程能力：** 三项核心流程已实现并通过所列宿主与真实界面验收；确认、版本、幂等与补偿回执可测试。保留旧系统、原存储与模型入口，不等于全平台、全设备或全套回归已经通过。

**专业判断能力：** 增加了事实边界、竞争解释、来源、反证、未知与复核流程。尚未经过运动科学/临床专家盲评或个人长期效果验证；不能根据工程通过数宣称教练判断已经达到专业水平。保守剂量保护也不是恢复预测模型。

未完成/未验证事项：

- 真实 DeepSeek 回复质量与语义推理的专业评估；自由文本数值审核偏保守，可能回退有价值的改写。语义安全不是形式化证明。
- 真实登录账户跨设备同步、历史 local 档案迁移归属、第三方设备服务器绑定；本轮只接真实会话作用域并验证本机隔离，不能宣称旧 App 全域账号隔离已认证。
- 后台定时与推送；关闭应用时不会执行。无需伪称周日晚自动在后台完成。
- 任意自然语言整份课表重排、无结构参数的 V4 直接执行修改；无法可靠识别时保留原记录、给出已知部分和最多两个关键追问。
- 比赛倒推周期、扩展测量 UI、完整营养计划引擎仅保留合同；阶段与历史耐受缺失时仍显示未知。
- 真实 Garmin/COROS 链路、Safari/iOS、无 Web Locks 浏览器均未实机测试；无 Web Locks 时拒绝 R5 执行，保留预览。
- 上述原有全套失败和本地二进制资源限制仍需对应维护。正式上线还需仓库所有者审阅 PR 和独立部署。

代码回滚：尚未合并时直接保留/关闭 PR，不影响 master。若以后合入，在独立分支 revert R5 的合入提交并经 PR 审查；不要重置主分支或覆盖历史。

用户操作回滚：确认卡或周草案点撤销，以补偿记录恢复；若课程后来已改/已开始或症状有新修订，撤销会拒绝覆盖，要求重新核对。不要通过清缓存回滚。移除 R5 界面也不删除新增测量、症状、回执或旧历史，旧版本可能不能展示新类型，数据仍保留。上线前按原备份流程保存用户数据。
