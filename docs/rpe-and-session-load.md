# 整课 RPE 与 Session Load（设计，尚未进入决策）

本文件只描述下一版合同。当前产品仍使用冻结的整课 RPE 1–10。这里的公式不写入疲劳分、Decision、课表或长期能力。

## 现在已经在用的合同

- 问题是：「这节训练整体有多吃力？」
- 只接受整数 1–10。空白是未记录，不是 0，也不是自动评分。
- 旁边的用力说明是产品引导，不是经过验证的中文版量表。
- 不把某一分数强制对应配速、心率、项目或剩余次数。
- 整课 RPE 不等于某一组或某一次的 RPE，也不等于现有疲劳规则分。
- 切换训练会清掉还没保存的草稿。
- 有可靠训练开始记录时，保存绑定该实例；重复确认不覆盖已有记录。
- 上传训练没有可靠 `trainingOccurrenceId`。上传侧只关联 `confirmedImportId`，明确不是冻结训练实例。

## 0–10 兼容设计（未迁移）

下一版可以把下限从 1 扩到 0，表示「完全不费力」，仍是整数。未迁移前：

- 存储、校验和界面继续拒绝 0。
- 旧的 1–10 记录保持原值，不平移、不重标。
- 0 不能拿来填补空白。空白仍是未记录。
- 如果将来迁移，读取侧要同时接受旧 1–10 和新 0–10，并在每条记录上标明刻度版本。决策侧在迁移完成前继续忽略 0。

## Session Load（未用于决策）

定义：

`Session Load = 有效整课 RPE × 有效训练时长（分钟）`，单位 AU。

有效整课 RPE：当前刻度下的整数，且状态为已记录。0–10 迁移前，1–10 才有效。空白、冲突、看不清都不是有效 RPE。

有效训练时长：已记录的整课时长，换算成分钟。建议接受范围是 1–300 分钟。短于 1 分钟或长于 300 分钟先标成待核对，不自动乘。

处理规则：

- 只使用整课时长，不把热身、休息或某一组的用时再加一遍。
- 混合课用这一节的整课时长乘整课 RPE，不拆成跑步 AU 和力量 AU。
- 没有整课时长时，不用分段用时之和代替。结果是未记录，不是 0。
- 采集时间是用户确认整课 RPE 和整课时长的时间。不回填到训练开始时刻。
- 同一节重复确认不改已保存的 AU。
- AU 不是疲劳分，不是受伤概率，也不是不同项目之间可以互换的负荷。
- 没有个人校准前，AU 只作为记录，不触发加量、减量或比赛安排。

## 现有疲劳分：最小方案，本批不改

下面两项会改变数值或状态语义，所以只记录，不实施：

1. `memory.fatigue || 20` 会把有效的 0 当成缺失并写回 20。最小改法是只在值不是有限数字时才用 20，并补一条「保存 0 后再读取仍是 0」的测试。影响：当前默认 20 的空记忆不变；真正写出的 0 不再被抬高。
2. `AthleteState.performance.rpe` 读取最近一条 `RPE_RECORDED` 时使用 `payload.rpe ?? payload.hours ?? payload.value`。主观恢复也写在同一事件类型里。最小改法是只接受 `evidenceType === "SESSION_RPE"` 或明确的 `payload.rpe`，跳过 `SUBJECTIVE_RECOVERY`。影响：今日状态里的整课 RPE 不再被下一条恢复分覆盖；Decision 若间接依赖这个字段，需要单独回归。

另外：空记忆的默认分是 20，但 `freshMemory.band` 写成 `ready`，而 `bandOf(20)` 是 `fresh`。展示上没有反馈时已改为 UNKNOWN，公式和 band 没有改。
