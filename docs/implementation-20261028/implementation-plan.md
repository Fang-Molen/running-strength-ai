# 方坤整体整改：Codex 实施任务书

> 给执行者：按任务顺序实施、测试、复核并记录证据。每个任务先核对实际源码，再用合成数据建立失败用例；不要把本计划当成已经实现的功能。使用当前环境可用的执行计划工作流；如适用，遵守仓库 AGENTS.md。

**目标：** 让方坤持续使用个人有效事实，自动联网回答和提出有依据的候选，并安全地衔接计划、跑步、力量、饮食和恢复。

**架构：** 在现有应用上增量修复：事实与证据有来源及版本；对话按意图和限制范围分流；在线模型负责分析与候选；正式写入经过预览、版本核对、确认和持久回执。优先复用现有模块，禁止为完成清单而平行造第二套系统。

**技术：** 交接包为 TypeScript、React/Vite、Node、IndexedDB/localStorage、服务端 SQL。实际实现与命令以执行时源码为准。

**完整规格：** 与本任务书一起提供《方坤全问题解决方案与复核（联网常开完善版）》：https://chatgpt.com/library?file_id=libfile_e8e401434ca48191bfbf67fccd97839a&account_id=personal 。本任务书用于执行；规格包含 54 项问题、恢复状态机、联网并发、专项能力和反例。无法访问时不能声称已覆盖规格，先完成本文件明确任务并列出未核对部分。

- [ ] 1–52 周保留既有能力，分开长期阶段方向和近周具体课程，注明阶段目标、进入/退出条件、复核点、依据及未知；继续沿用当前首周正式确认边界，未来周为条件草案。
- [ ] 支持 400、800、1500、3000、5000、10000 米及其他长跑的专项差异，目标可行性结合实际成绩、经验、日程与限制；不得用设备预测伪装成绩或保证结果。
- [ ] 跑课保留热身、主课、组/轮、休息和完成情况；无匹配时保留原始分圈供核对；单次表现不能断定永久短板或动作诊断。
- [ ] 力量按目标、经验、器材和实际跑课选候选；区分组次重量、RIR 和单位；不自动加重或无理由换动作。替代说明目标和非等价点。

**验收：** 8/12/24/52 周区分阶段与近周；六个跑步距离不套同一长跑模板；两轮不同休息结构不展平；路线/条件变化降低可比性；缺 RIR 不虚构确定加重；不同反馈第四周结果可不同；漏练不改写历史；正式变更需预览、确认和冲突检查。运行 `npm run test:cycle`、`npm run test:coach-loop` 及跑课/力量/UI 新测试；动作资源与训练剂量另标专业审核状态。
