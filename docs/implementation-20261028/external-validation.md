# 外部能力边界与验收操作单（2026-10-28）

本轮只使用合成资料、本地浏览器、签名测试身份、隔离 PGlite 和假模型。以下真实账号、设备、生产数据库、付费模型及部署操作没有执行。历史其他环境费用仍为待核对，不能记为零。

| 入口 | 源码提供的能力 | 必需环境/范围 | 当前不能声称的能力 | 代码依据 |
| --- | --- | --- | --- | --- |
| Garmin | 分项同步、活动/分圈、日内资料、账号隔离与保存回执 | 已绑定本人账号、后端会话；以每项同步报告为准 | 登录不等于全部数据读取或导入完成 | `src/lib/health/garmin-sync-runner.ts`、`garmin-sync-status.ts`、`garmin-account-owner.ts` |

获得相应授权和环境后，再按以下次序执行；每步保留版本、时间、主体、原始回执、失败原因，日志不包含凭证。

1. **后端与数据库**：在生产备份的隔离副本依次应用 001/002/003；检查 schema 探测；完成 down/up 演练并核对历史行未丢失。部署前记录服务端 commit 与构建产物校验和。`FANGKUN_COACH_SCHEMA_READY` 不能替代实际探测。真正生产迁移另行批准。
2. **登录与多人隔离**：两名测试账号、两个浏览器上下文，依次请求各自快照；交叉读取/撤销均失败。退出和换账号时，旧响应不能显示或写入新档案。旧本机历史不得自动认领给新账号；正式计划、身体数据和食品记录另做完整隔离检查。
3. **真实品牌**：记录授权范围与工具能力，再读取一条已知活动及各类已知健康记录；核对原始时间/单位/来源/分段，预览后确认。重启和另一设备分别检查保存状态。撤权/过期/掉网/限流/无数据分别验收，不能都显示“同步成功”。
4. **Safari 实机**：iPhone/iPad 测试小屏、键盘、安全区、下载、刷新、离线重启和系统回收。备份只能宣称下载已触发；要求人工检查实际文件完整性。验证隔离恢复候选读取，而不是假称已覆盖现有数据。旧冻结标签恢复写入无法隔离时，继续拒绝主动覆盖恢复。
5. **实际模型与费用**：先核对历史费用，核准价格和小额测试预算；完成授权后才启用真实调用。每次记录请求 ID、模型/返回版本、用量、预留与结算状态。取消、超时、输出拒绝可能已花费，不重复自动重试。不重新生成既有整套题库，优先已存答卷离线回放，再做少量差异案例。
6. **专业评价与长期反馈**：请具备对应专项经验的教练及相关专业人员评审可执行剂量、禁忌、误拦截/漏拦截、营养和特殊人群；保留拒绝及反证。用实际后续表现和独立反馈检查建议，不能以一次表现或工程通过率宣布因果与长期效果。

真实演练记录模板：`caseId / 日期 / 版本 / 测试主体代号 / 环境设备 / 授权范围 / 输入来源及修订 / 预期 / 实际回执 / 数据变更 / 费用状态 / 专业评估人及范围 / 未验证项 / 结论`。未执行栏保持 `NOT_RUN`，历史费用保持 `UNRECONCILED`。
