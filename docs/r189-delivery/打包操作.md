# R189 交付维护

本文件面向后续开发者。打包工具仅做文件整理与完整性校验，不运行程序测试、不调用模型、不部署。

```bash
python3 evaluation/r189/package-delivery.py --prepare
python3 evaluation/r189/package-delivery.py --fingerprint
```

`--prepare` 读取精确回退 ZIP 并校验 baseline.json，生成逐文件 SHA256/CRC、差异和修改文件列表。交付生成文件自身不计入修改列表；完整 source-manifest 除自身外覆盖全部可交付源码。此模式不会生成交付 ZIP，也不会写 PASS。

运行最终验收前记录 `--fingerprint`，把实际运行结果填入 `验收结果.json`，把待定稿报告另存为 `交付报告.md`。日志引用使用 evidence/r189 下真实存在的相对路径。必须填实际环境、覆盖、计数和阻断项；FAIL/BLOCKED/SKIP 都可以诚实交付，PENDING/RUNNING 不能作为已定稿结果。

最终源码修订后须重新核对受影响验收证据；不要为了绕过指纹门控而给旧日志填新指纹。运行时/测试/资源指纹包括 src、public、server、scripts、migrations、依赖锁和构建配置，排除 docs/evaluation 以允许最后添加交付文档。

```bash
python3 evaluation/r189/package-delivery.py --package --receipts docs/r189-delivery/验收结果.json --output /workspace/fangkun/delivery-r189
```

输出目录必须为空，防止混入过期包。所有 ZIP 是普通独立压缩包，每包小于 8,000,000 字节；超过时自动切分为多个各自可解压的文件集合。工具校验源码包加 3D 包的合并目录与候选源码完全一致，另复制未改动的 R188 回退包。最终报告、结果、修改列表和 checksum 同时独立提供，方便手机查看。

历史报告仅作为追溯材料保留。不要使用旧版本打包脚本生成本轮交付；它们使用不同基线及固定目录。
