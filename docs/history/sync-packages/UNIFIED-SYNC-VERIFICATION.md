## 交互检查覆盖

- 设置、健康、首次引导和主屏幕欢迎页进入同一个「设备与数据同步」窗口；账号连接与文件导入共用该窗口，一次展示一个平台。
- 已选平台、待处理任务与预览在切换、关闭重开时保持一致；同一同步任务的重复点击合并，读取本身不自动保存。
- 官方授权链接使用当前浏览上下文，回调返回对应平台。首次引导跨整页跳转后恢复原步骤、平台和已填昵称。
- 授权失效回到重连入口；个人接入门禁到期回到接入码输入。Strava 的错误档案不展示无法完成的 OAuth 按钮。
- 新数据经明确勾选和保存才进入原有数据链；相同来源活动不重复保存。保存合成跑步时，原始 `360.1` 秒未取整，已有档案和训练保留。
- 相同来源 ID 的时长/距离冲突展示新旧值，保留已有记录和手填更正；缺失值与实际零分别处理。
- 320px 大字体下长来源标识正常换行；健康指标的口径与测量时间可展开，展开不改变 checkbox，未知测量时间仍保持未知。
- 原 Garmin 手动/部分健康返回、COROS 活动预览与同步进行中关闭重开经过本轮定向回归；精确计时、明确保存和原有记录保留。
- 网页/PWA如实显示原生健康能力不可用；浏览器模拟没有假称已经取得手机系统健康权限。

正式构建的五组分别为：导航 23、云数据预览/保存 13、320px 大字体详情 13、COROS 最小流程 9、Strava 错误档案 6，共 64 项。浏览器测试全部使用新建合成档案，API 在本地拦截，外部请求被阻止。结果不等同于真实厂商联通测试。

开发与正式构建报告包含修复前后证据。正式导航首次检测将 Garmin 卡片保留的负边距视为子容器溢出；窗口/页面宽度正常且截图无越界，因此将断言改为检查实际滚动容器及预览/详情，没有为通过测试改产品布局。修正后导航 23 项通过。

## 本轮重点修复与数据边界

云连接和个人 MCP 分别验证了 callback 交换、刷新以及异步 cookie 加密过程中断开。被取消的旧授权不能重新安装凭据；迟到凭据尝试撤销，上游不能确认时保留提示。重新开始连接后，旧回调成功、失败、重放或不匹配都不能删除新的 pending 状态。

上述竞态及一次性状态协调的保证限于同一运行实例。Cloudflare/Vercel 多实例上线仍须配置共享原子状态、撤销与刷新协调，详情见接入文档。

账号和运动员切换有前后端边界校验。原始时长、来源身份、健康指标口径及测量时间保留；RMSSD、SDNN和未知 HRV 协议不相互替代。新增导入复用原来的 `saveDeviceRows`，未改恢复计算、训练计划存储、课程完成逻辑或方坤的模型调用权限。

- **Strava 个人 MCP**：个人部署门禁、本人真实授权和官方能力验证；目前仅连接与工具发现，不将活动写入训练或 AI 数据链。

本包没有部署线上服务、发布手机安装包、替用户注册厂商账号、执行真实授权或调用付费模型。具体环境变量、回调和接入步骤见 `UNIFIED-SYNC-README.zh-CN.md`、`docs/integrations/` 与 `native/fangkun-health/README.md`。
