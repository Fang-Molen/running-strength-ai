## 已确认的代码原因与修复

| 原因 | 修改后的行为 |
| --- | --- |
| 用“指标＋日期”跳过已有健康记录 | 同来源同观测键允许更正，保留原 id 和旧值；不同来源保留独立记录 |
| 睡眠秒值先转成一位小数小时 | 带来源的睡眠保留秒值及精确换算；界面显示小时/分钟，原始值不丢失 |
| 把 bodyBatteryHighestValue 当身体电量当前值 | 明示“当日最高（非当前值）”，不用于当前疲劳判定 |
| 日界固定 UTC+8 与本机日历混用 | 请求日按本机日历生成，并核对 API 返回日期；仍需用真实账号核对跨时区场景 |
| 部分 HRV/睡眠请求失败仍报同步完成 | 显示部分同步和失败项；最近完整同步时间与尝试报告分开保存 |
| 健康首页只在首次挂载读取数据 | 监听健康保存、存储和页面返回，刷新最新记录与来源选择 |
| 多来源直接拼成趋势、HRV 越高直接标绿 | 共享来源投影；相同来源/统计口径/HRV方法内比较，冲突待选择；变化不直接标为好坏 |
| 教练主要读取正式训练事件，独立健康记录未接入 | 每次提问读取日历日数据摘要；保留“每日背景”与“本次训练事实”的区别 |
| 截图确认后只在独立证据库 | 增加“用于健康分析”，显式导入已确认睡眠、HRV、静息心率、血氧；平均运动心率不会变成静息心率 |

没有删除历史记录、自动改课或自动把独立导入活动绑定为训练开始事件。

## 方坤如何判定数据能用在哪里

“数值有效”仅表示结构、单位、范围、日期及来源满足当前用途，并不等于设备测量完全准确。来源优先级按用户核对选择，不固定认为手表一定胜过手工记录。

| 信息 | 可用于什么 | 必须保留的边界 |
| --- | --- | --- |
| 当天疲劳感、主观恢复、疼痛打卡、当天疼痛日志 | 恢复复核、追问、疼痛优先限制 | 自述是有效信息；没有填不代表“不疼/不累”；不诊断伤病 |
| 当天睡眠、近期同来源睡眠记录 | 描述睡眠变化，与其他信号联合复核 | 手表睡眠与自报区间代表值分开；估计时长不当作精确测量 |
| HRV、静息心率 | 同来源个人近期变化的辅助证据 | HRV方法或统计口径不清时限制比较；不能混 RMSSD/SDNN；不把二者当两条独立确认信号 |
| 夜间平均心率、运动平均心率 | 各自原定义下的背景信息 | 不替换静息心率 |
| 身体电量、准备度、压力、血氧、步数等 | 按原始定义展示和辅助核对 | 算法分数不能单独批准训练；日最高电量不是当前值；不由血氧推导训练处方 |
| 日程实际时长、公里、已填实际强度 | 实际执行与训练结构统计 | 完成标记不等于完整实际明细；未知时长另计缺失，不当0 |
| 正式训练内的分段、实际组、RPE、绑定反馈 | 保留原本训练事实与复盘链路 | 日历日健康背景不能自动补入这些事实 |
| 手表确认导入活动 | 列示最近活动、已知距离/时长 | 可能与日程重复；尚未建立对应关系时不相加计算总负荷 |
| 计划动作与课程 | 计划覆盖、连续强度日、跑步/力量重叠 | 计划不等于做过；计划肌群覆盖不等于实际刺激量 |
| 已确认饮食 | 已记录营养的小计与缺项 | 识图估算保留不确定性；记录不完整不能断言摄入不足 |
| 比赛目标、周期阶段 | 限制临时加量、解释阶段性安排 | 当前目标不冒充历史比赛信息；不能为凑比例自动加课 |
| 未确认截图、无法读取的存储、未来日期、过期值、来源冲突 | 保留为待核对/历史/缺失提示 | 不进入当天疲劳判断；不补0、不补正常、不静默取平均 |

同日多来源默认标“来源待核对”，在健康指标详情选来源后，页面与教练使用同一投影。手工原记录和其他来源不会删除。选择来源不意味着证明该来源正确。

## 疲劳复核的具体规则

输出包含：已有证据、采用/排除理由、当前判断、建议和下次复查信息。

1. 当天自述疼痛或疼痛日志有记录，优先核对部位、功能、诱发动作；好看的手表数据不能解除限制。
2. 信号分成主观感受、睡眠、自主神经相关指标三类。HRV与静息心率属于同一类；设备复合分数不重复计票。
3. 当前工程复核线：睡眠较前7天可比记录均值少至少1小时；HRV低至少15%；静息心率高至少5次/分。前7天至少3个可比记录日才显示参考均值，缺失日不补0。
4. 上述数值是应用的保守复核规则，**不是医学诊断标准，也不是已经针对该运动员校准的疲劳阈值**。7天短基线不能代表长期正常值，跨设备、环境、测量条件变化需再核对。
5. 多类信号同时出现：提示恢复压力，给出减低主课要求/轻松恢复的候选方向；仍需热身表现、近期实际训练与症状核对。单类信号：先观察核对。证据不足：明确不确定。未见这些信号：只说明所查记录中未见，不确认“完全恢复”。
6. 当天疼痛或多信号状态进入教练的“禁止据此加量”约束，但不写成所选训练的疼痛事实，不自动执行改课。
7. 跟进：热身后反馈腿部感觉、疼痛及同类动作表现；课后RPE；次日睡眠和主观恢复。下一次提问重新读保存记录。此版本没有新建后台主动提醒，也未完成基于长期预测误差的自动阈值校准。

## 训练均衡的当前能力

按最近7个日历日复核，而非要求每天练得一样。

- 区分课表跑步/力量节数与已有实际反馈节数。
- 实际时长按用户填写的轻松、中等、高强度分列，未知时长与未知强度单列；不是心率分区统计，不强制套80/20。
- 核对连续两日课表标注高强度，以及同日强度跑和力量的顺序、间隔、下肢重叠；这是待核对线索，不直接宣布过量。
- 动作有有效catalogId才统计计划肌群覆盖；未知动作列为缺口，不靠名字编造肌群。
- 根据现有比赛临近/减量上下文提醒，不能为补齐肌群临时堆训练。
- 跑步公里、力量重量、组数不相加为一个“总负荷”；设备导入和日程未去重关联前分开列示。

尚不能由这份摘要证明实际训练已均衡。完整判断还需要实际组数/负重/RPE、重复跑分段与休息、近期完整负荷、目标与阶段，以及同类表现的可比条件。此版本不提供未经验证的肌肉疲劳百分比、损伤概率或精确比赛预测。

## 专业表、普通表、无表：三种模式统一支持

用户当前使用专业运动手表模式。三种选择是数据入口和默认展示差异，不是三个不同的教练系统，也不是设备品牌自动连接授权。

| 模式 | 主要输入 | 数据不足时 |
| --- | --- | --- |
| 专业运动手表 | 实际导入的健康指标、活动与可用明细＋主观感受 | 未导入HRV/分段不会凭品牌补造；睡眠缺失可独立自报 |
| 普通健康手表 | 已有睡眠、心率、活动，手填力量/训练反馈；若真有有效HRV或详细数据仍可使用 | HRV不是必填项；不拿另一品牌算法补值 |
| 无手表 | 手动实际训练、睡眠区间、疲劳、疼痛与主观恢复 | 可做有限恢复复核、课表结构分析；不要求购买设备，不制造身体电量 |

睡眠等可比趋势加明确的主观反馈，即使没有HRV也可报告“所查记录未见上述不利信号”，同时列出缺失项；仍不等于完全恢复。没有足够数据时先补实际训练与感受，不锁死功能。

修改包括：模式说明显示在健康记录与恢复页；缺失手表睡眠时开放自报区间；已导入的有效指标不因模式默认隐藏而丢失；切换设备类型刷新上下文、保留历史。底层规则不按设备价位或版本名称推高判断信心。

**未在本包承诺所有品牌自动直连。** 原有Garmin同步和文件/截图入口按实际能力运行；其他品牌账号连接需要各自授权及适配，不能因为选了普通表或专业表就显示已同步。真实各品牌设备与手机验收仍待完成。

## 用户入口与数据流

健康 → 指标详情 → 核对日期/来源/统计口径 → 选择展示与分析来源。

方坤对话 → 展开“本次可用数据” → “分析今天的健康和疲劳” / “评估这周训练均衡”。每轮问题重新组装数据；显式日期、昨天、今天与所选训练日期分别处理。新提到的疲劳不被已保存的好数值抵消。

设备截图 → 核对并确认 → 已确认设备证据 → “用于健康分析”。未点击时仍只在独立证据库，避免未授权健康数据写入。原图保存与备份逻辑继续保留。

教练模型摘要包含健康来源和缺失状态，既有云端授权与输出约束保留；本地规则回答可离线运行。不能把“数据已进入摘要”说成“云端模型已完成真实调用验证”。

## 验收标准

以下是真机待验步骤，**不能以单元测试代替**：

1. 在原站备份用户数据，用同一Garmin账号对照同一天：睡眠时长、日静息心率、昨夜HRV、当日最高电量。截取双方相同统计页面，不拿当前电量与最高值比较。
2. 同步后不重新进入健康页也更新；修正当天数据再次同步，条数不重复，值更新、旧值可追溯。
3. 人工制造某日请求失败，应显示部分同步；恢复后重试。登录失效及无该指标也不伪造数值。
4. 手工睡眠与手表睡眠同一天不同值：显示来源待核对，选择后趋势与方坤引用一致；另一个来源保留。
5. 验证昨日数据明确标历史，今天未填不显示正常。手机跨日、时区变化核对API返回日与本机日。
6. 方坤未选训练时，仍能回答今天健康；选旧训练后问今天，仍用今天数据；问本次则核对对应日。
7. 当天有疼痛，正常手表分不能批准加量；新聊天疲劳反馈不能被已有记录否认。
8. 同一活动在日程和设备导入同时存在，不能重复加总；只完成标记无实际时长的课程明确缺失。
9. 确认截图后点击用于健康分析，重复点击不重复记；平均运动心率不变成静息心率。
10. iPhone Safari和主屏模式核对来源弹层、长来源名称、键盘、滚动、关闭、底栏遮挡及重新打开；未真实执行前不报告通过。
