# 给 Grok Build：一次性长任务 · 方坤 BUILD 40 集成验收

这份 ZIP 是完整源码候选，解压后 `app/` 是项目根目录。用户允许在**独立预览**中逐步开放方坤受控计划编辑和可控联网，但禁止覆盖正式线上版。无需每个小阶段向用户索取确认，连续推进开发和测试。

1. 先阅读 `BUILD40-REPORT.md` 与 `AGENTS.md`，在独立预览工作区安装依赖、运行完整 typecheck/build/全量测试。不要删除历史训练、饮食、身体数据。
2. 先验证方坤聊天中的“受控解冻 · 未来力量计划修改与撤销”：对比、确认、写入同键审计、刷新回读、拒绝过期计划、疼痛/骨痛阻断、已完成训练不可变、撤销、跨标签冲突。当前实现只支持力量动作减一组；不得声称可安全改跑步周期。
3. 再验证“设备截图 / 身体数据 / 单次分段识别（本地免费）”：本地OCR（若浏览器支持）或手动转录、编辑、来源时间与单位、确认后原图与证据的 IndexedDB 存储、刷新与导出。iOS Safari 若没有 TextDetector，明确显示不可用；不能伪造 OCR 结果。
4. 继续开发**不依赖付费大模型**的可用识图：优先打包离线 OCR（需实际引擎和语言数据）；如选择联网 OCR，必须用户针对该图片单独授权，服务端代理、密钥不可暴露、可取消、无网络自动降级。训练和身体记录默认不上传。
5. 将 IndexedDB 设备证据纳入现有备份/恢复；没有用户确认、可信时间和来源时不能写入正式训练事实或身体中心。跨品牌智能设备只按字段/单位处理，不假定 Garmin 或 Apple 特有格式。
6. M3个人响应候选需要多次绑定训练及24/48h反馈；M7记录决策来源与用户接受/拒绝。不能将OCR识别值当作医学诊断或直接驱动自动加量。
7. 输出真实预览地址、完整源码 ZIP、回退包、实际浏览器/手机尺寸测试、失败列表及未完成事项。所有未测试项标记 NOT TESTED。禁止自动部署或覆盖线上正式版本。
