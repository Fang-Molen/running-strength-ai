# BUILD 14.2 候选修正：服务端唯一来源绑定与按路径精简提示

## 平台阻塞

BUILD 14.1 平台验收中，严格 JSON 和否定式安全结论已经通过。剩余确定性阻塞是：36/35/34 秒回答内容正确但模型漏填完成事件 ID，导致 `SERIES_TIME_SOURCE`；中间一次恢复缺失时模型漏填缺失训练的开始来源，导致 `SERIES_POINT_SOURCES`。另有多组连接阶段 25 秒超时。

## 修正

1. `groundSeriesResponseSources()` 在服务端解析模型 JSON 后，根据回答里的具体秒数反向查找正式 `observations`。只有某个秒数在全部纵向点中唯一归属于一次训练时，才补上那次的 `sourceEventIds`。不存在的秒数、重复秒数无法唯一归属、冲突记录都不会被补证据。
2. 回答使用“分别/依次”列出与训练数相同的秒数时，服务端按最早到最近顺序核对。顺序写反返回新的 `SERIES_TIME_ORDER`，不能因为来源齐全而通过。
3. 恢复回答明确写出“未记录/缺失/数据不足/不能判断”时，服务端为主观恢复缺失的纵向点补上其可靠训练开始来源。这只证明该训练点存在且没有可用恢复评分，不制造评分或趋势。
4. 模型提示按 `candidate-route`、`formal-compare`、`formal-series` 三条路径拆分。正式纵向不再携带饮食、旧数据、候选路由等无关规则；正式比较不再携带纵向细则。25 秒上限不变，目标是减少无关上下文和输出混杂，不能宣称已经解决上游超时。

## 安全边界

这是服务端确定性来源绑定，不是为模型答案伪造引用。补齐来源必须来自已经验证的正式事实包，并满足唯一匹配。模型写错数值、错顺序、长期能力结论、冲突代选或缺失当正常仍会被拒绝。事实、证据、Strength、TrainingFact、跑步结构、课表、Decision 和事件合同未改。
