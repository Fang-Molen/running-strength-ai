## 这次实际做了什么

- 登记饮食、饮食快捷记录：拍照/相册 → 预览 → 手动点击联网识别 → 核对食物、品牌、份量、五项营养 → 一次提交整餐 → 刷新统计。支持选择食物库准确品牌/规格；不把其他品牌汉堡自动套用。图片估算、标签读取、数据库数值分开标注。未知值保持未知，已知零热量可正常记录。
- 网络识别使用服务器 DeepSeek API，默认 deepseek-flash。图片识别走独立路由，不修改教练推理模型的设置。识图失败、结果截断、图片过大、离线、错误访问码、额度不足均显示可操作反馈；不会生成假结果或自动写训练事实。
- “记一笔”：新增完整截图识别入口，保留所有文字。检测到多条结构化数据时只保存完整笔记，引导到详细记录，避免只保存第一条。最多三张附件，文字上限扩到 20000。
- 训练上传：在独立访问码配置后可走 DeepSeek 结构化提取；仍经过既有 normalize → 草稿 → 人工核对 → 确认，未知日期/恢复不补零，计划不当已完成。保留原截图供本次核对，关闭会取消/忽略未完成的提取。未配置新访问码时仍保留旧服务路径及原权限边界。旧教练复盘模型服务没有在本次解锁或替换。
- 设备/健康截图：新增联网文字识别选择，使用原有校对和保存流程；设备证据单独标明 NETWORK_OCR_REVIEWED 来源。不会凭图片自动推断医疗结论或恢复许可。
- 课表图片：识别文字供核对；同时保存原图片。PDF/文本课表的原文件也真正保存在 IndexedDB，可导出。资料与可执行课表保持明确区分；PDF不直接识别，可选页面截图。旧版只有文件名的条目无法凭空找回原文件。
- 本地 OCR：独立共用模块、初始化失败可重试、串行工作、超时反馈、图片压缩及 iPhone 图片读取失败降级提示。

## 发布端接入（本包不含任何真实密钥）

必须在原 Cloudflare Pages 项目同时部署根目录 functions/ 和前端构建产物 .output/public；不能只拖拽上传静态产物。原 Garmin Functions 和 assets 路由保持原样。

服务端设置：

| 名称 | 用途 |
| --- | --- |
| VISION_ENABLED | 字符串 true 才启用 |
| DEEPSEEK_API_KEY | 已充值账户的 API 密钥，只放服务端 secret |
| VISION_ACCESS_TOKEN | 自行生成至少24字符的随机访问码，单独提供给本人，在 App 填写；不要用 API 密钥充当访问码 |
| DEEPSEEK_VISION_MODEL | 可选，默认 deepseek-flash；只使用实际支持图片的模型 |
| VISION_RATE_LIMITER | 可选 Cloudflare 限流绑定，有绑定时失败即停止调用 |

入口：个人与数据 → 联网图片识别；图片识别卡也可填写访问码。访问码只存在当前页面内存，刷新后重新输入，不进入备份。服务状态检查只验证配置存在，不验证真实模型额度或视觉效果。此访问码方式供当前个人试用；如公开多人使用，应接既有账号鉴权和持久化配额，不能共享本人访问码。

请求固定到 https://api.deepseek.com/chat/completions；不接受客户端传上游URL/API密钥/任意提示词。当前请求上限4MiB，图片预处理单张20MB以内，网络超时45秒。JSON输出、禁用思考模式、最多6000输出token，仅点击触发，不后台重试。不存储或日志输出原图与密钥。浏览器取消后会请求中止，但不能保证上游完全免除已发生的计费。

官方依据（2026-10-17查阅）：
- https://api-docs.deepseek.com/guides/vision/
- https://api-docs.deepseek.com/api/create-chat-completion/

本功能是“向识图模型发送图片”，没有另做品牌官网实时搜索。普通食品照片的数值是估算，品牌准确值优先以清晰标签或已核对的数据库条目为依据。
