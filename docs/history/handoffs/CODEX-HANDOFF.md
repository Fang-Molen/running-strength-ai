按 Asia/Shanghai 日历日聚合浏览器本地饮食条目，区分目标与已记录摄入。没有记录保持 UNKNOWN，不当作零；别日不借用；不完整记录不能证明实际热量赤字，也不能证明一次掉速是能力不足。问答走服务端 xAI，数值回答必须有饮食与目标两个来源；不当因果断言拒绝。比较两节训练时不夹带单日饮食上下文。

## BUILD 08.2：恢复和身体反馈的可追溯问答

教练读取直接复用冻结的 `projectOccurrenceEvidence()`：只接受真实 `TRAINING_STARTED` ID 绑定且通过投影校验的 RPE、睡眠、主观恢复、酸痛、疼痛。`SUBJECTIVE_FEEDBACK` 的恢复及酸痛不再被漏掉；来源说明保留分值、部位和原始事件 ID。无绑定或无效记录不混入本次训练。恢复评分冲突保持 null 并先追问，不从两条中挑选。

酸痛与疼痛在教练事实包中分开；只有实际绑定的疼痛记录或原有计划上下文中的疼痛才触发疼痛安全约束，单独酸痛不冒充疼痛或伤病诊断。肌肉骨骼证据结论仍为 UNKNOWN。模型若宣称完全康复、没有伤病风险或酸痛就是伤病，回答会被拒绝；报出 RPE、睡眠、恢复、酸痛、疼痛的具体数值时，必须引用该类型与数值对应的 FACT 来源。这是输出校验，问答仍由模型完成，不使用固定回答冒充教练。

最后收口又补了一道窄范围校验：若模型在答案中声称本次已记录疼痛或酸痛，必须引用相应类型的本次训练 FACT；未绑定记录和训练开始事件不能替代该来源。确定地说“没有疼痛/酸痛”也会被拒绝，而“尚不能判断是否恢复正常”仍可正常回答。这是安全校验，不是用关键词生成教练回答。

新增测试覆盖绑定/未绑定、恢复冲突、酸痛/疼痛分离、来源数值对齐及无写入。训练事实、证据投影、Strength、TrainingFact、跑步结构、Decision 和课表语义未改。用户的接受、拒绝、修改、Override 权保留。

## BUILD 08.3：用户确认的身体反馈补记

在选择有可靠 `TRAINING_STARTED` 的训练后，教练页提供酸痛/疼痛、部位和 1–10 程度输入；只有点击确认才写一条对应事件。酸痛使用既有 `SUBJECTIVE_FEEDBACK` 的 `SORENESS` 类型，疼痛使用既有 `PAIN_RECORDED`，两者均带可靠 `trainingOccurrenceId`。同一训练的相同类型、部位和程度不会因重复点击写第二条。没有自动修改课表、Decision 或疲劳分。

已有 RPE/恢复补记的去重现在检查冻结证据投影的全部有效记录；旧的 `SUBJECTIVE_FEEDBACK` 恢复记录也能挡住重复补记，不再只检查 `RPE_RECORDED`。切换训练时清空未提交草稿，避免误绑。这些变化不增加事件或跑步 Schema。
