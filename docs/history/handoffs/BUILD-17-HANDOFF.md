## 目标

解决“上传一次训练后，大脑只有模型复盘、没有稳定教练分析”的缺口。用户确认 ACTUAL_ONLY 训练后，页面先产生确定性的有来源复盘；模型深度复盘仍是附加层。模型失败时不冒充模型回答，但基础教练判断仍可用。

## 新能力

`training-coach.ts` 只读取已确认导入记录，不写 AppEvent、课表、Decision、疲劳分或 TrainingFact。

单次训练：

- 同距离重复跑显示首段、末段及差值，引用对应两个分段来源；只称本次观察，不判定长期能力。
- 力量训练使用“已记录完成 N 组”，明确未记录组不能推断为实际没做。
- RPE、恢复、疼痛、酸痛分开；酸痛不等于疼痛或伤病，疼痛不作诊断。
- 高 RPE 且缺恢复时先追问；疼痛或低恢复时只允许保持、减量或恢复边界。
- 单次 ACTUAL_ONLY 没有原计划，禁止比较是否完成或偏离计划。

跨次观察：

- 至少 3 次、至少 3 个不同 Asia/Shanghai 日历日。
- 只有重复跑结构、轮次、次数、距离和实际用时全部对齐，才输出逐次中位数观察。
- 不同结构、缺槽位、距离不同或不可比较时保持 NOT_COMPARABLE，不比较快慢。
- 即使 36/35/34 秒连续出现，也只输出观察，不写长期能力已经提高。
- 疼痛、低恢复、高 RPE 缺恢复会让调整候选降级为 ASK 或 HOLD_OR_REDUCE；任何调整都要求用户确认，不自动应用。

页面在确认训练后新增“即时教练判断”和“连续训练观察”。确认记录仍是 `recordMode=ACTUAL_ONLY`、`canonicalOccurrenceId=null`，不会伪造 trainingOccurrenceId 或绑定既有证据链。
