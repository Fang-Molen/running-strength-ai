# 方坤 v72 本地接入候选

这份已包含热身逻辑和页面交互的实现，取代此前未接完的 fangkun-v72-codex-handoff.zip。

可用入口：
1. 添加训练：日期/类型 → 训练前热身开关 → 选择跑步或力量任务、5/15/30/40分钟 → 编辑动作和主课 → 保存。
2. 首页对应课卡的“训练前热身”，或“进入这节训练”：进入同一日程ID，开始热身或“本次不使用”，之后进入原主课。
3. 热身中可暂停/继续动作或组间休息计时，逐项确认完成、实际不同、跳过；关闭刷新后恢复。计时不自动标完成。
4. 健康 → 我的形象/形象与目标：打开可调3D参考，前侧背视角，基准/目标四种局部形变通道，独立保存；下方数字目标仍按原逻辑保存。
5. 力量动作详情和热身使用同一athlete角色。精细肌肉模型仍是独立的解剖图谱；它位于第二页力量区及添加动作选择入口，不是体型模拟角色。

关键逻辑：
- 跑前、速度/间歇与上肢/下肢/全身力量准备有不同清单；完整档增加专项量及恢复，时间窗含调整和恢复，不强制等满。
- 本次跳过不关闭今后的热身计划；热身未执行主课不会被写为主课完成。
- 预备重量明确填写，自重填0，未知不猜；更换力量主项后需重新确认预备组。
- 实际数量和时间分开；未计时/未填重量/未填休息保留未知。跳过没有零值完成事实。
- 热身与主课通过确切课次ID关联。混合课可关联同一轮热身到两个部分；同一部分再练需重新做热身选择。恢复已开始主课不重新拦截。
- 开始、暂停和输入有持久保存检查；重复点击/版本冲突不重复记录；损坏记录不静默覆盖。热身和跑步共用写锁。
- 新热身记录、计时和输入、外形参数进入完整保险箱备份；不改变旧字段和历史计划。

验证：979项测试通过（含25项本次专项）；类型检查和生产构建通过。11个新热身动画共220个实际蒙皮姿势采样通过有限坐标、位置范围和鞋底/地面检查；新人物42组姿态/外形、28组形变组合、5组真实着色器通过。QA内有日志和实际GLB渲染图。这些不是浏览器操作截图，也不是动作的专业生物力学审校。

明确剩余：
- 精细原图人物身份尚未重建：当前仍通用脸、UV贴身衣服及蓝鞋，没有完成原图脸型、独立衣褶、宽松短裤和白鞋。女性可调模型未提供，页面明确提示。
- 外形通道是手动参考，不依据体重自动预测肌肉或脂肪分配；模型高度/骨长固定，未做个人扫描校准。
- 本轮没有浏览器、iPhone Safari/主屏幕实机操作与性能验收；旧应用大路由包问题仍在，冷加载大小需手机确认。
- 没有部署或修改线上用户数据。不是“全部设计已完成”或“已上线”报告。

合并与上线：
source/为完整候选源码，同时包含v71训练流程改版。PATCH-FROM-V71.json与PATCH-FROM-V69.json列出差异和SHA。先比对现有最新工程，再按差异合并；不要盲目整包覆盖其他已更新工作。src/lib/core的268个文件、营养库18个文件、functions的2个文件与上传v69逐字节相同。

在原工程运行 npm ci、npm test、npm run typecheck、npm run build，再在手机验收：
A. 添加跑步/力量热身；切换时长能确认替换清单，保存后回到同一日程。
B. 热身计时与组间休息互斥；关闭/刷新继续；记录实际不同、跳过剩余并开始原主课，名称/距离/动作一致。
C. 混合课两部分、重复训练、重复点击、多窗口、配额失败都不写错主课完成。
D. 3D角色加载/失败重试、播放变暂停、慢放、视角限制、形变独立保存、目标数字保存。
E. Safari及主屏幕模式底部安全区、键盘弹起、关闭嵌套弹窗和页面滚动恢复。

部署沿用现有Cloudflare Pages项目 molen-fangkun 及原域名，不另建站。静态产物是 .output/public；原functions按现有项目方式发布。无发布权限就交源码，不报告上线。交付时返回实际合并版本、测试和手机验收结果。
