# 给 Grok Build 的一次性长任务：跑步力量 / 方坤本地智能可交互预览

## 用户明确授权及范围
用户授权：在**独立预览开发副本**中，为实现方坤提出训练修改、用户确认、撤销与试运行，允许调整原冻结的**计划写入权限/相关权限门控**；不等于取消 AI Brain V3.3 的安全规则和数据契约。不要直接解冻线上正式版，不要改写训练历史，不要静默迁移或清空 localStorage，不要覆盖线上站点。发布前必须向用户展示改动清单和独立预览 URL 并征得确认。冻结权限变更记录为 `PREVIEW_ONLY`，可回退，保留安全否决、用户确认、28天保护等现有合同；涉及任何合同冲突先在报告中列出并采用保守行为。

## 最重要的交付目标
1. 用本 ZIP **完整源码**恢复项目并安装依赖，先跑 `npm run typecheck`、相关单测、`npm run build:dev`（或说明构建环境限制），保存原始失败清单。不要凭旧报告宣称通过。
2. 在现有方坤 UI 接通**本地免费智能**：正常问题不依赖 API key；用户可用四种风格（专业均衡、严格督导、温柔支持、数据分析）；风格只改变表达，不能改变安全等级和事实。联网可显示状态，但**本轮严禁接入网络智能体、联网知识检索、任何线上大模型或第三方 AI 请求**；隐藏/禁用高级线上请求按钮，禁止隐式回退至模型 API。不要把用户训练、饮食、健康记录发送到远端。
3. 只读关联真实训练、饮食、身体记录，保留事件ID/日期/来源，未知数据保持未知；新记录后前台刷新；断网可用，PWA 关闭后后台常驻不作为本轮承诺。
4. 在**原有计划系统**里实现训练调整完整闭环：聊天提议 -> 旧/新计划并排差异 -> 风险、证据和周期影响 -> 用户确认/拒绝/修改 -> 提交前重新核验计划版本、风险和权限 -> 原子保存计划版本/审计事件 -> 可撤销至上一版本。只允许未来尚未执行的计划槽变更；已完成训练事实、原始快照及历史事件不可变。不得创建平行计划系统。
5. 异常训练（例如200×400m=80km重复跑）、带伤高强度、疑似骨应力损伤等必须安全阻断自动计划提交；明确解释并建议安全替代或专业评估。用户确认不能绕过高风险阻断。普通负荷修改也不能因为一次RPE高就直接推翻周期。用户可拒绝提案并记录 override。
6. BUILD34 的安全分流补丁已覆盖到 `src/lib/core/coach-local-safety.ts`，500题开发集和知识审核规范在 `quality/build34/`；这些不是已核验医学知识或可自动学习的模型权重。核验导入路径及实际问答调用链，保留测试案例原始数据。新建至少100道不参与开发的独立挑战题；安全高风险误判逐项列出，绝不声称“500/500代表准确率100%”。
7. 四种风格各测试训练、营养、恢复、安全、计划修改、连续追问；同一案例安全结论必须一致。至少覆盖：无API key、断网、记录新增/删除、跨日期、重复事件、过期计划版本、重复点击确认、撤销、刷新、手机375/390/393/414宽度、PWA数据不丢失。
8. 用真实浏览器交互完成“新用户首次打开 -> 方坤问答 -> 新建训练记录 -> 再问方坤 -> 计划提案 -> 用户确认 -> 刷新后计划一致 -> 回退”的端到端演示；不能只给截图或单测。
9. 不删除食物库、热量、身体记录、现有训练日志和通用设备能力；不得重新引入 Garmin 专项 UI。无密钥写入源码；不要要求用户给任何生产密钥。

## 交付与验收报告（一次性完成，不要每步问用户）
- 给独立预览链接（如果平台支持），明确是否真的可访问；给可下载完整源码 ZIP 和回退 ZIP。
- 提供实际命令、测试数、失败数、typecheck/build结果、浏览器端到端步骤及视频/截图（如支持）。未执行的标 NOT TESTED。
- 列出所有变更文件、原冻结权限临时调整的差异、权限仍然禁止的操作、隐私/网络调用审计和回退方式。
- 如果依赖/环境阻断，修复可修复的构建问题；仍阻断则保留源码和可复现日志，绝不能假称上线或通过。
- 预览版只在独立副本操作；正式上线、用户真实数据迁移及网络智能体功能均需后续单独授权。

## 产品方向
方坤是人人可用的本地优先教练，常规训练/营养/恢复问答免费，不因GPT额度耗尽失效。高级大模型申请/赠送额度是**未来功能**，本轮明确关闭。训练计划由方坤长期主导提案，用户最终确认，安全引擎对危险自动执行有否决权；知识/记忆使用现有 V3.3 M0–M8 体系，未经核验的题目不可自动晋升为科学知识。
