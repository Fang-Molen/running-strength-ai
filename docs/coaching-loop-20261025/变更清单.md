## 二、各项要求的实现

### 1. 统一方坤判断链（`src/lib/coach/loop/unified-answer.ts`、`coach-sheet.tsx`）
- R4 知识和私人教练回答不再抢先返回，改为同一条回答链的输入，和训练计算、疲劳恢复、目标、历史判断一起使用；本地分析和联网分析照常运行。
- 联网时，R4、个人条件和当前有效资料作为事实发给现有 DeepSeek 入口，不超过 8000 字上限。模型和入口都没有改动。
- 回答下方单独显示「个人目标与专业参考」和追问。

### 2. 各板块信息同步（`effective-profile.ts`、`effective-host.ts`）
- 当前有效资料统一为：体重、年龄、性别、身高、目标，每项都标明来源、时间和版本。
- 时间最新的记录为准；时间相同时实测值优先；没有时间的记录排在最后。
- 两周内不同来源数值不一致时提示核对，不擅自合并；缺失的项保持未知，不按 0 处理。
- 饮食页、健康页、教练简报、状态引擎、私人教练和 R4 都用这份资料，不会再各用各的体重或目标。
  - 已验证：录入 66 kg 实测体重后，饮食页蛋白建议从 112 g/天 变为 106 g/天。
- 运动员档案保存时记录时间，并通知所有页面。
- 保存资料、更正、同步、建议变更时，教练视图都会重新读取数据。

### 3. 信息不足也要有用
- 先回答已有信息能回答的部分。假设标为「假设：」，不写成用户事实。
- 每次最多追问 2 个问题，优先问会改变建议的冲突项；已有的资料不重复追问。
- 联网提示词同步写入这些规则，并说明补充资料后建议哪里变了、为什么变。
- 私人教练还没确认条件时，按已有资料先给出一般方案，并标明「尚未确认」；依赖健康筛查的精确数值暂不给出。

### 4. 改课建议由用户决定（`suggestions.ts`、`suggestion-host.ts`、`coach-suggestions-panel.tsx`）
- 建议类型：移动、对调、替换、取消、减量，以及配套的热身、恢复、饮食提醒。
- 触发规则：
  - 疼痛或安全限制仍在生效；
  - 当天恢复指标低于本人基线；
  - 赛前两天内有关键课；
  - 两节关键课相邻（保留跑步和力量，只移动力量课）；
  - 课时超过已确认的可用时间；
  - 漏练关键课（只提醒，不叠加补课）。
- 卡片显示：修改原因、原安排、建议安排、影响、依据、不确定性、配套建议。
- 可选操作：接受、编辑后接受、暂缓、拒绝。编辑只能降低剂量或改日期，不能加量。
- 写入前重新核对最新依据；依据有变化时，原建议标记过期并重新预览。未处理的建议不会执行，过了日期自动过期。
- 写入方式：
  - 移动、对调走 R4 课程流程：预览 → 确认 → 回执 → 可撤销；
  - 取消、减量、替换走带锁的日历写入，保存前后快照，可撤销。
- 通知：
  - 今天页卡片、方坤 → 复盘里的建议栏、方坤导航角标；
  - 系统通知需用户手动开启，并得到浏览器授权后才发送。

### 5. 备注与长期反馈闭环
- 方坤备注和用户自己的备注分开保存，并关联到日期和课程。
- 接受、编辑、暂缓、拒绝、撤销、过期、依据变化和后续跟踪都写入历史记录。已完成训练的实际记录不会被修改。
- 课程日期过后，按实际完成情况和 RPE/疼痛把判断标为支持、削弱或撤回。拒绝后原安排顺利完成，也会记为该规则依据偏弱。
- 资料被更正时，依赖它的备注标为「依据已变，待复核」，保留历史和变更原因。撤销调整后，对应备注标为撤回。
- 未处理的建议和跟踪结论会进入方坤的事实，方坤可以据此解释和修正判断。

### 6. 保留 1000 字与年龄覆盖
- 问题上限从 200 字恢复到 1000 字（`COACH_QUESTION_MAX`）。
- 联网回答按需要组织长度，上限 1000 字，超出时在句末截断；不强制凑字。
- 年龄：12–80 岁照常记录、提问并获得一般建议，只暂停没有可靠方法的精确计算：
  - 未成年人：暂停精确热量和蛋白数值，给出生长期饮食原则，力量训练需在监护人知情和教练指导下进行；
  - 65 岁以上：照常估算并附注意事项；
  - BMI 低于 18.5：不提供减重缺口；
  - 热量目标：不低于 1200 千卡和估算基础代谢中较高者；
  - 期限要求的缺口：不超过维持热量的 20%。

### 7. 测试与工具
- `npm run test:coach-loop`：新增闭环测试，并包含合入的 R4、私人教练、训练模型、分析等测试，共 210 项。
- 浏览器关键流程验证脚本：`evidence/coach-loop/flow.mjs`（使用合成数据，阻断模型请求；`evidence/` 不入库）。
