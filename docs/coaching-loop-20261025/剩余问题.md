# 剩余问题与限制（2026-10-25）

以下各项没有完成或没有验证，不应视为已通过。

## 未做或暂停
1. **没有部署，也没有调用付费模型。** molen-fangkun 上 push 到 master 后不会自动部署（上一轮已确认 10 分钟内没有更新），需要由仓库所有者在 Cloudflare 里处理。联网提示词的修改（1000 字、假设标注、改课建议）只有部署后才会生效，而且没有经过真实 DeepSeek 调用验证。
2. **历史费用待核对。** 本轮没有读取、修改，也没有按零处理费用台账；各环境此前的 DeepSeek 用量需要到 DeepSeek 后台核对。
3. **受控网关没有合入。** 865b032 那条线的服务端鉴权、同意和持久额度账本会关闭现有问答，所以没有采用。要启用的话，需要先在服务端装好可信的鉴权和额度服务，再单独评估。

## 已知限制
4. **移动和对调只适用于结构完整的已保存课程**（沿用 R4 course-flow 规则）。原始 V4 自由文本课表的条目不能通过建议卡移动，会提示原因；减量、取消、替换不受这个限制。
5. **建议规则是确定性的产品规则，不是经过验证的生理模型。** 阈值有：HRV 低于基线 85%、睡眠比基线少 1 小时、赛前 2 天、减量到 60–70%，结果只作参考，并在卡片里标明了不确定性。
6. **反馈闭环只看计划记录的结果、RPE 和疼痛原因**，没有用手表的客观负荷来评估。规则权重不会自动调整，只记录支持、削弱或撤回。
7. **系统通知只在应用打开时由页面发送。** 后台推送需要 Service Worker 推送服务和服务端，本轮没有实现。
8. **当前有效资料只统一了体重、年龄、性别、身高和目标。** 训练日、伤病限制等其他字段仍由各自页面管理。聊天还不能直接修改身体测量或整份计划（865b032 的限制仍在）。
9. **本机数据按运动员作用域隔离，不等于登录账户隔离**（沿用 865b032 的说明）。
10. **其他运动员作用域**：应用目前固定使用 `local`，按运动员区分的计划键在当前用户身上等价于原来的键，现有 V4 计划不会丢失。多运动员切换的场景没有做浏览器验证。

## 已有、非本轮造成的问题（与未改动的 master 完全相同）
- 7 项测试失败：`first render does not depend on browser training and day records`、`learning sources respect existing local and offline network policy`、`plan lines require an actual imported plan…`、`shared exercise view exposes local 3D…`、`void and field corrections invalidate old muscle evidence…`，以及两项因为 Windows 不允许创建符号链接而失败的 CLI 测试。
- master 的 `npm run build` 在 Windows 上无法启动 vite（spawn ENOENT），用同样的环境变量直接调用 vite 构建可以通过。修复在 `codex/fangkun-runnable` 分支的运行时提交里，按要求没有并入 master。
- `functions/api/coach-chat.js` 的 `@ts-nocheck` 有一条 eslint 报错，master 原来就有。
