## 后续开发的固定边界

1. 在独立功能分支开发，通过 Pull Request 交付；不直接写 master，不强推、不自动合并。
2. 保留训练、健康、饮食、Garmin/COROS、历史记录、用户备注和原始证据；不清缓存、不重置数据、不以新结构静默覆盖旧记录。必要迁移另做可恢复设计。
3. 不自动部署，不开启 auto-merge、不触发部署工作流；合并和发布由用户另行决定。
4. 保留当前 DeepSeek 接口、鉴权和数据保护；不未经授权调用付费模型。
5. 问题与回答上限保持 1000 字，不强制凑字。年龄覆盖不收窄；不适用某计算方法时仅限制该精确计算，仍提供有依据的一般或条件式回答。
6. 信息不足仍先给有用回答，未知不填 0、不编造；最多追问 1–2 个会改变结论的问题。
7. 改课、配套安排和教练备注区分建议与执行；计划变更先展示差异并由用户确认，执行前核对最新版本，保留撤销和历史。
8. 只做改动相关及受影响路径的必要验证；已有报告的通过数不能替代本轮执行，也不重复无关全量测试。
