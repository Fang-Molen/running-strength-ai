# 方坤产品主规格（整合去重版）

2026-10-28；以本文件、执行任务书和执行时最新源码为准。历史审计仅供追溯，不能当作当前故障或已完成状态。

## 1. 产品目标

方坤是个人运动教练和 App 中控。它理解运动员的历史与目标，结合实际训练、手表、力量、饮食、疲劳和恢复，回答问题、提出短期与长期候选、协调各模块，并依据执行反馈和修正持续跟进。桌宠是随时登记和提问的分身，不建立独立数据体系。

核心链路：实际资料→准确归属和计算→按问题选择依据→模型理解和解释→直接回答或给候选→必要时预览确认→执行反馈→更新判断。每一环的缺失、冲突与失败都要能解释，不能以模型写得流畅代替正确。

## 2. 已确定的产品决定

- 在线模型分析默认开启，普通问答和追问自动进行，不逐问征求同意；允许用户主动关闭。网络、鉴权、额度和服务故障明确显示。联网模型推理与网页检索不同，没有真实检索不能假称已搜索。
- 只读查看、导航、知识回答及方案讨论直接进行。新增记录的预览卡上，一次“保存”即确认；修改正式计划、历史记录、删除或改变手表关联须展示具体前后差异并确认。用户已有记录和已完成训练不得被覆盖。
- 数据按用户、时间、来源、单位、协议与版本处理，过去一年及更早已有记录按问题检索；目标、历史 PB、预测和当前实测分开。未记录不是零，缺资料不能成为无关问题的全局拦截。
- 疲劳与健康判断区分观察、参考、推测及明确限制；正常指标不能解除独立疼痛限制，严重症状及时提示。App 不冒充疾病诊断或提供无依据的精准疲劳百分比。
- 个人事实、关键反证和风险不能因压缩丢失。模型回答、实际联网、用户确认和持久保存必须显示真实状态。服务端鉴权和预算保护继续有效。

## 3. 第一批完成后用户应该能做什么

1. 手表同步或已有活动中选择 A，系统识别同活动重复来源，显示正确距离、跑步用时、配速及已有分圈；同日 B 不误合并。
2. 在训练详情点桌宠补 RPE/酸痛；输入一句话后能看到可编辑草稿，点一次保存，反馈绑定 A，不新建一节跑步。
3. 用户问“这节怎么样，明天怎么练”，方坤理解是 A，读取相关训练、个人状态、已有日程和关键缺项；本机计算可追溯并被模型使用，直接给结论、依据和有条件的候选。追问可延续对象。
4. 如需改课，展示目标、变更与冲突，确认后写入并返回结果；失败或过期不假报。相关建议在数据更正后重审。
5. 桌宠饮食输入框显示本地搜索与可用联网结果；选择食物、份量与餐次后一次保存。来源、每份/100g、生熟和缺失清楚，网络故障仍能本地/手动登记。

**边界：** 真实手表/DeepSeek、在线食物服务、iOS真机、正式恢复及专业有效性有独立验收；无环境不能声称已通过。桌宠系统桌面是后续方向，首批只实现 App 内功能并分离业务服务。

## 4. 以后分批补齐的能力

- 专项：400/800/1500/3000/5000/10000 米及长跑，按目标、能力、训练经历、日程、器械与限制选择，不使用同一万能模板。
- 周期：近周执行、8/12/24/52周阶段方向、条件与复查；比赛变动、漏练及反馈触发重评，不追补或叠加已完成历史。用户偏好的 3 周训练＋3–4 天调整可作为个人偏好，非通用规则。
- 力量与营养：目标、动作、逐组/休息、个人经验及跑力冲突；已记录餐不等于全天完整，活动与总消耗不重复计算。
- 个人长期画像：把近期状态、长期能力、同协议基线与观察性反应分开，历史更正或反证可撤销旧结论。
- 专业知识：按来源、版本、适用人群、范围、反例和复核日期纳入，需实际专家审阅和真实效果评估；不得以测试数量或群体研究替代个人效果。

## 5. 数据不足时必须回答的内容

针对每个用户问题，说明①已读取哪些资料及时间；②能确认什么；③缺失、冲突或未发送什么；④原因属于未采集、读取失败、知识/规则缺口、模型未收到、外部/专业未验证中的哪类；⑤最少补充或下一项验证。普通问题先回答能确定的部分，不让用户反复填写整份资料。需要多长历史取决于判断类型与可比性；不得将某个固定窗口当作准确度或医学标准。

## 6. 不做假承诺

不承诺任意问题都有唯一准确答案，不虚构数据或来源，不以少 token 为由省掉决定性证据；不未经确认写课表，不自动宣称同步、恢复、联网检索或系统桌面功能成功。真实模型和专业训练效果需后续授权和独立验证。
