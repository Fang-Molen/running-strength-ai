## 必测贯通场景

虚构用户一年记录 → 选择一节手表跑 A（同日有 B） → 输入“这节怎么样” → 问“明天呢” → 联合恢复与既定力量提出候选 → 预览并确认改课 → 完成反馈 → 更正一圈 → 旧结论过期 → 更新候选 → 检查训练/健康/饮食页面一致。记录每一步来源、请求、回答、版本和回执；没有真实模型就明确假服务。

## 必须反馈：能力不足与不能判断的情况

提供单独清单，每项写：用户关心的问题 → 已有数据 → 缺失数据及时间覆盖 → 数据是读取不到还是未采集 → 现有程序能确认什么 → 为什么不能作更精确判断 → 最小必要补充或验证 → 当前候选及风险 → 负责模块/代码与优先级。区分“数据不足、知识/规则不足、模型未收到资料、实现缺失、环境未验证、专业验证不足”，不要把它们统一写成“请补更多数据”。即使不能准确判断，也要给可靠的部分回答。
