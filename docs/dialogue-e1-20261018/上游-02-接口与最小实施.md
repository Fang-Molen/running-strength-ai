# 02｜接口合同与接入位置

## 与R13/V74的边界

```
HOST: 身份绑定、事件快照、科学计算、风险、证据校验、候选决策/授权
  ↓  ApprovedCoachBundle（不可变、版本绑定，含来源）
E1: 篇幅档位、情绪开场、受控释义、一个关键追问、逐片段组装
  ↓  InternalPreview + Trace，永远 authorizedForDelivery=false
E1 Guard: 原文、顺序、来源版本、问法、风险与权限完整性
  ↓  PASS / BLOCKED
HOST: 既有下游专业安全门控 + maySendToAthlete + planMutationAuthorized
  ↓  目前R13=内部预览，禁止运动员发送和改课
```

字段见 `src/contracts.ts`。`schemaVersion=E1.0`、`bundleId`、`factVersion`、`sourceRevision` 均必填。最小上游要素：

| 字段 | 用途 | 缺失行为 |
|---|---|---|
| 批准句 `claims` 及不可变 id | 准确性保护 | `BLOCKED`，不改写 |
| `factVersion/sourceRevision` | 同一事实快照与更正 | `BLOCKED` |
| `sourceIds` | 数字事实溯源 | 源信息缺失的 `fact` 类型拒绝 |
| `revokedSourceIds` | 拦截过期数值 | 涉及过期来源则拒绝 |
| `safetyLevel` / approved safety line | 安全优先 | urgent 缺安全句拒绝 |
| `allowedActionClaimIds` | 只显示被允许谈论的候选行动 | 未在白名单中拒绝 |
| `permissions` | 禁止发送/改课 | 任何 true 直接拒绝 E1-R13 研究路径 |
| `alreadyAskedQuestionIds` | 控制重复追问 | 若无法可信追踪，优先不追问，不能猜测历史 |

### 片段优先级

- `required`：结论、关键不确定性、安全警示、正式更正通知，任何模式都必须保留。
- `supporting`：补充限制或已批准解释；standard/deep 显示。
- `detail`：展开深度与候选对照；deep 显示，**但依然只能来自被批准的信息**。
- `glosses`：由宿主明确批准的通俗释义；E1 仅插入，不改写。

### 三档表达是软预算，不是截断字数

- `brief`：优先用事实+风险+必要不确定性；默认简单问题/用户要求简要。参考目标 60–160 中文字。
- `standard`：增加最重要的限制与解释；参考目标 150–350 字。
- `deep`：可加入所有宿主已批准的补充内容，分层展开；参考目标 300–650 字。
- **以上只是可用性研究目标，不是强制字符裁剪**：复杂风险提醒、专业限制必须完整保留，字数可能超出。

## 已实现模块与暂不实现

- 已实现：受控篇幅、显性情绪小词表、只读已批准片段、释义插槽、一轮最多一个追问、已问ID去重、撤销来源阻断、动作白名单、不得发送或写计划、异常拒绝、原文回验。
- 暂不实现：真实R13数据接口适配；真实LLM表达自由改写；跨轮语义记忆恢复；医疗评估；任何发送或持久化训练记录。

## 真实工程的关键细节

1. `ApprovedCoachBundle` 只能由可信服务器/应用内部教练引擎产生。**客户端表单或用户输入不能自行创建“已批准”声明。**
2. 训练原始数据与“模型生成意见”不能因字段同名即升级成可信事实；来源审核属于宿主，不属于 E1 的字符串核验。
3. 若输出完成后训练发生新更正、当前用户变化、计划版本变化，宿主发送门控仍需重验 `factVersion` 和权限；本模块的通过证明不了后来版本有效。
4. 有撤销来源但尚有旧引用时**整体拒绝 E1**；不要简单从答复隐藏某个分段，避免旧结论和新结论相互矛盾。
5. 每轮推荐记 audit 元信息（不记不必要用户私密文字）：bundle hash、使用claim IDs、输出模式、追问 ID、阻断代码、最终交付权状态；按照现有隐私/删除合同处理。
6. 多轮题必须使用**真实、冻结的上下文快照**；“昨天说过”的情绪化提问不能变成“确实发生过”的证据。
7. 生产向运动员发送始终由宿主现有安全门控最终决定。当前 E1 参考实现直接固化 `authorizedForDelivery=false`，不得用文字开关绕过。
