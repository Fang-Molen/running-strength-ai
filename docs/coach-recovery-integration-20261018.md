# 训练复盘与健康背景联动（2026-10-18）

本次沿用既有离线复盘、R173 计算器、健康存储和判断历史；没有新建 AI Brain，没有接入模型或远程服务。

## 实现范围

- 普通训练复盘和已保存课程复盘均可读取当前运动员、对应训练日期的健康背景。训练分段仍来自原事实层；日级健康信息独立标为 `DAY_CONTEXT`，不会变成本课的测量记录。
- 复用 `REC_SLEEP`、`FAT_RHR`、`FAT_HRV`、`FAT_HRV_CV`，计算睡眠小时、静息心率相对个人中位数变化、lnRMSSD 相对个人基线变化和历史 lnRMSSD 变异系数。
- 只使用截至分析时间已知、协议可比的数据。设备、来源、统计口径、HRV 算法以及已提供的测量方法分开；不将 SDNN 当 RMSSD。缺失、冲突及未来更新分别列明，不填零。
- 普通文字复盘实际引用这些数值。只有适用的 `SESSION_CONTEXT` 解释引用恢复背景；计时误差、动作幅度或器械差异等解释不会附会这些来源。
- 健康来源和基线成员纳入已有依赖签名。更正后，依赖旧版本的解释撤回，保存过的旧复盘继续保留；仅推进分析时间不会撤回判断。
- 疼痛打卡及独立疼痛日志优先于训练探索；疼痛限制沿用已有对话门控，跨轮和 JSON 恢复后保留。普通医学路由标志不会被伪造为疼痛诊断。
- 修复固定有效 HRV 序列的变异系数被误判不可用的问题。标准差为零可产生 CV=0；分母为零仍不可用。

## 接入与来源

`coach-recovery-context.ts` 是只读存储桥接，调用方明确提供运动员、日期和分析时间。`recovery-quantitative.ts` 为纯计算适配器，接收已经隔离运动员的快照；本身不读取存储或网络。

入口为 `coach-dialogue.ts`、`coach-offline-workspace.ts` 和 `coach-offline.ts`，统一交给 `buildOfflineReview`。新增字段为可选恢复上下文，不迁移、删除或覆盖既有训练和健康数据。

原始来源、单位、有效样本、缺失原因在 `recoveryContext.quantitative`、`ruleCalculations` 及复盘详情中保留。历史依赖单列 `health-day:日期`，不冒充训练 occurrence。生成复盘不写正式计划；已有复盘保存功能继续保存判断历史。

## 限制和待验证内容

- 数学计算和合成场景通过不等于疲劳阈值获得科学核准。本轮没有新增综合疲劳分、能力分或自动减量/停训/医学回归规则。
- 基线采用既有规则的数据要求：此前7个日历日内至少5个可比记录日用于个人变化，CV需要完整7日；这些是当前计算合同，不是医学恢复标准。缺失日不补零。
- 日级日期边界仅用于窗口索引，不代表测量时刻。桥接显式提供本地 UTC 偏移；跨夏令时切换、旅行时区变化及设备原始时区仍需单独核对，未声称完整支持。
- 无时间戳的旧疼痛日志只作为当前可见的安全线索，明确标注录入时间未知；不加入精确历史依赖或量化基线，也不回填到跨日历史分析。不能据此反推当时已知信息。
- 旧健康更正若没有可恢复的历史版本，历史分析降级为不可用，不补造旧值。没有明确训练日期的未保存聊天不擅自绑定今天的健康数据。
- 多条件相关变化只形成待验证解释及观察任务，不证明因果。压力、疾病、营养、环境等全部影响因素尚未被统一校准，不能称为“疲劳已完全标准化”。
- 本轮验证使用内存合成记录，无真实运动员数据。浏览器离线刷新与手机上的安装版本仍需独立验收；源码构建不表示已更新手机 App。

## 复现和回退

从源码根目录使用已安装依赖运行：

```sh
node --import ./scripts/test-register.mjs src/lib/core/coach-quantitative.test.ts
node --import ./scripts/test-register.mjs src/lib/health/recovery-quantitative.test.ts
node --import ./scripts/test-register.mjs src/lib/core/coach-recovery-integration.test.ts
npm run typecheck
npm run build
```

交付包提供全仓测试逐文件日志、运行脚本与实际计数；未执行或失败的检查不得记为 PASS。增量清单提供修改前后 SHA256；合并前核对现有文件，若基础版本不同则做差异合并。回退时恢复包内原文件并删除本轮新增文件，保留用户本地存储及其备份。
