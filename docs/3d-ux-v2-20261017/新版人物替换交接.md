# 新版人物后续替换准备

用户最新范围：先做好后续替换准备。此检查点不替换当前人物，不启用新视觉版本，不部署。新 GLB 与动作资源本体尚未完成。

## 固定接入点

- 身份：`coach-male`、`coach-female`、`muscle-soft`。个人形象后续使用同一角色资产体系，外观偏好与身体实测继续分开保存。
- 版本：每次资源交付使用独立 `assetVersion`；相同路径不覆盖不同文件。使用 `/media-v2/<version>/...`。
- 动作：沿用原有 76 个稳定 ID；模板已列出男女 152 个待审核绑定。热身、扩展及自定义另列，不用相似名称猜动画。
- 合同：`src/lib/strength/media-v2/registry.ts`。精确匹配动作 ID、角色 ID 和版本；人物、动作、关键帧来源都要一致。新资源目前 `approvedMedia=[]`，`visualRelease.enabled=false`。
- 2D：每动作 4—6 帧，附同一模型 SHA-256、剪辑 ID 和时刻。来源不能用单独生成的相似人物图片代替。
- 缓存：`cache.ts` 先下载至独立暂存代、核对字节与哈希，完成才切换；失败保留旧代，只管理媒体缓存，不清除训练或健康记录。该接口尚未接入运行中的旧播放器。

## 收到资产后的只读检查

准备独立暂存 `public/media-v2/<version>/`，根据模板填写实际模型与动作元数据，保持原动作 ID。工具不会拷贝、批准或启用资源：

```bash
python tools/media-v2/check_replacement.py incoming-manifest.json staged-public
python tools/media-v2/probe_glb.py staged-public/media-v2/<version>/male.glb
```

检查缺文件、SHA-256、字节数、错误 HTML、路径逃逸、外链依赖、角色版本、绑定重复、关键帧模型与动作对应。结构成功仅返回 `STRUCTURE_CHECKED_REVIEW_STILL_REQUIRED`，不意味着画面或动作通过。模板直接执行应返回 `BLOCKED`；这是预期拒绝。

必须补做 Khronos 官方格式验证、男女及肌群视觉检查、代表动作接触/关节/穿模审校、真实 iPhone 性能与交互检查。审核状态只能随证据更新，不能为了使工具通过批量改为 APPROVED。

## 替换顺序与回退

1. 先把男性、女性、温和肌群和代表动作做到定稿标准，并导出同角色关键帧。
2. 核验模型单位、朝向、骨架、形变范围、道具挂点、许可和可编辑母版。现有 Three.js r169 不混用其他版本 Loader。
3. 在独立副本把统一合同接入 `demo/provider.ts`、`exercise-demo.tsx`，再逐一覆盖今日训练、计划、动作库、热身、历史与个人形象入口。此运行时迁移本轮未执行。
4. 新入口失败仅降级同角色批准关键帧/封面或文字待补充；新视觉启用时一并清除旧人物和线条人回退，不能同时混用两套形象。
5. 验收真实版本缓存升级与断网重开，确认训练、饮食、健康和计划存储不变，再决定交 Grok 独立验收。当前检查点不等于发布授权。
6. 回退源码使用本目录交付说明所列的 V74 八个基线分包。此次未做数据迁移；回退代码不删除 localStorage/IndexedDB/训练记录。后续新媒体切换失败保留旧资源，不清理非媒体缓存。
