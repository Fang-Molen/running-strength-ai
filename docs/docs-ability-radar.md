# 六方图：用户能力评分公式

代码：`src/lib/ui/ability-radar.ts`（纯函数），`src/components/ability-radar-card.tsx`（纯 SVG）。测试：`src/lib/ui/ability-radar.test.ts`。
窗口为近 28 天。对比线用同一套公式，把 asOf 往前推 30 天再算。数据达不到门槛时显示「待评估」：分数为 null，图上画虚线轴和空心点，连线跳过这个顶点。

| 维度 | 公式（0–100） | 门槛 | 置信度 |
|---|---|---|---|
| 力量 | 60·min(1, 每周力量课次数/2.5) + 40·中高强度占比（RPE≥7，没有 RPE 时看强度≠EASY） | ≥3 次力量课 | ≥8 高，≥5 中 |
| 耐力 | 60·min(1, 周跑量/30km) + 40·min(1, 最长单次/15km)。没有距离时改用分钟：周 180 分钟、单次 90 分钟算满分 | ≥3 次跑步 | ≥10 高，≥6 中（按分钟估时最高为中） |
| 速度 | 只取 ≥3km 且有时间的跑步，用最快 3 次的平均配速线性换算：7:30/km = 0 分，4:00/km = 100 分 | ≥3 次带配速的跑步 | ≥8 高，≥5 中 |
| 恢复（进阶版/专业版） | 几项平均：睡眠 (h−5)/3·100；HRV 50+(7 天均值/28 天均值−1)·250；静息心率 50−(7 天均值−28 天均值)·10；Body Battery 7 天均值（只限专业版） | ≥7 天数据，每项 ≥7 条 | 3 项以上且 ≥21 天为高，≥14 天为中 |
| 恢复（基础版） | 打卡疲劳（轻松 8 / 一般 6 / 很累 3）×10，和手动睡眠分取平均 | ≥7 天打卡 | 固定为低 |
| 稳定性 | 80·(按计划 + 0.5·有改动)/已结束计划课数 + 20·(1 − 因疼痛偏离的占比) | ≥6 节已结束的计划课 | ≥16 高，≥10 中 |
| 坚持度 | 60·(4 周里练了 ≥2 次的周数/4) + 40·min(1, 总次数/12) | ≥4 次训练，且最早一次距今 ≥14 天 | ≥12 高，≥8 中 |

只有 status 为 done、并且 actual.outcome 不是 missed 的记录才算“练了”。
