# 跑力负荷与 UI 优化交接

2026-10-29。基于 9263254 + Fangkun-GPT-Work-Handoff.zip + 上轮跑力原型。在隔离副本修改，未提交、部署、访问真实数据或调用付费模型。

## 已实现

- 原型拒绝结束时刻晚于分析时刻的训练计算整课 AU。
- 现有 CoachLoadMetricsPanel 内新增实验性跑步/力量实际记录。按所选 28 天范围展示，使用 analysis-host 权威快照和用户时区归属；显示距离完整性、已完成组、候选 AU、缺项和来源版本。无记录不视为休息，无 AU 不填零。
- 面板展开后动态加载事实读取模块，避免未使用时立即执行分析；监听训练更改和跨标签存储事件，并提供手动刷新。异步响应在依赖变化/卸载时丢弃，读取失败明确提示。
- 使用现有页面，不增加底部导航或新的负荷持久化来源。训练细节为只读，不改课表。

## 必须继续的工作（不能称全部完成）

1. 核对完整课时、评分采集及整课/分项归属；当前 AU 仍为候选。混合课目前保守不计算，需 occurrence 层整课指标只计一次，分项独立保留。
2. 完成力量按动作/组次/负重口径与跑步已知部分、完整性的汇总。目前只是已记录事实，不能从组数直接推断训练刺激。
3. 统一旧负荷趋势与新明细的时间、来源及范围：旧趋势北京时间、权威分析为上下文时区；长期查询须显式读取保留历史，不能把默认近90天读取说成全量历史。旧趋势和新明细尚未统一为同一个计算投影。
4. 完成日周汇总、曲线与版本化缓存；新增/补录/撤回/更正/删除后失效并重算，对照全量重算验证，禁止把无记录补零。此包未实现持久增量缓存。
5. 训练详情、桌宠、健康页、方坤问答共同读取同一投影；有记录就能查看依据和跳回训练，旧回答在依据修改后提示复核。此包只接了方坤现有负荷面板，未连接完整路径。
6. 浏览器验收：实际合成训练保存→桌宠反馈→负荷面板刷新→问答引用→更正→重载；包括切用户、隐藏/重开、失败后刷新、窄屏、长来源名、键盘遮挡。别用静态渲染冒称完整闭环通过。
7. 完成跑力组合科学研究与独立案例审查；疲劳/恢复曲线须有有效证据和适用范围，不用检索权重或任意组数生成生理评分。
