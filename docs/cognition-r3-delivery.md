# 第三轮候选：交付与验收边界

## 已实现

- 首周候选接受后，明确选择当天训练，创建独立 candidate 计划、冻结快照并进入原跑步执行页。目标不当能力；未知不当正常；修改后须重新接受，拒绝或证据失效时不新开练。
- 基础用户通过连续走跑记录热身、主课和放松；有基础用户保留轮次与独立休息。重复跑计划兼容层没有把候选秒数区间擅自折为一个目标成绩，原区间仍保留于候选。
- 明确完成或提前结束；结束事件、生命周期和会话反馈一并提交。还有未知或冲突主课时不能声明全部完成。返回不等于结束；结束后不再写分段。
- 候选训练历史提供明确训练编号的恢复入口；刷新后可继续或查看已结束训练、绑定24h/48h恢复观察。观察窗口±3小时为产品容差，不是科学阈值。
- 反馈保留自报来源及未知字段；高RPE、疼痛或低恢复会要求更新当前安全/恢复信息，影响下次解释与开练核验，不自动提高能力或增加负荷。既有预测/响应记忆仍保留，不将新的自报自动晋升为稳定模式。
- T23：保留两套设备原文、原值和来源；询问窗口/覆盖、原始来源、算法、单位、个人基线、RPE及当前症状。不能平均、挑选有利值、诊断疲劳或确认恢复正常。现症紧急安全规则优先。

## 多键事务的修改理由及范围

旧跑步开练依次写事件、训练记录和快照，后续失败会暴露不完整训练。新路径以 `fr255-running-tx-r3:` 不可变事务记录一次 `setItem` 提交整组实体；读取者从同一完整记录投影，写后回读确认。没有未提交的多键暂存数据。原事件、训练、计划及个人数据键不由新跑步路径覆盖。

浏览器跑步写入使用同源 Web Locks 串行化，并在锁内重读状态。不支持 Web Locks 时拒绝保存并解释。内存适配器测试模拟并发；尚未验证真实浏览器的锁实现。单条日志独立键防止不同客户端覆盖；冲突的计划分支均保留，计划变为不可用，不选最后写入者。

范围为本次400米跑步路径和跑步计划/快照；力量旧流程以及通用备份恢复没有升级为全域事务。不能声称所有历史多键写入都已原子化。冲突计划目前需新建独立计划编号后核对，未扩展通用冲突编辑器。

## 测试证据及版本

最终执行版本、源文件SHA-256清单、命令退出码、时间、依赖版本见 `evidence/round3/final-version.json` 与最终日志。中间失败日志用于定位，不作为最终通过证据。

新增场景覆盖服务层完整链路、不同基础、拒绝/失效/未来/休息日、疼痛冲突、开练及结束失败、部分写入、无操作写入、独立客户端交错提交、相同计划锁串行、计划分支冲突、延迟反馈、旧键不变、备份往返、SSR入口。既有第二轮可练天数及成绩更正测试复用并纳入最终完整回归。

## 失败与未验证

- 浏览器真实点击、刷新/多标签、390px显示、PWA/iPhone未验证。原因和原始工具拒绝见 `evidence/round3/browser-blocker.json`。未重复下载Chromium或尝试被阻断的浏览器地址。
- 没有可访问的本轮独立候选预览URL。HTTP/SSR/模拟存储通过不能替代真实浏览器验收。
- 干净依赖安装未重跑；复用第二轮依赖，版本明确记录。
- 运行期间实际断电、浏览器崩溃、真实localStorage配额和多个真实标签并发仍未验证；相关异常和交错由内存适配器注入。
- 部分写入/无效事务保留在存储中以便审计，读取者不投影；没有自动清理用户数据。
- 24h/48h响应为合成时钟测试，未等待真人训练后的自然时间窗口。设备输入为用户报告审计，不是设备平台实际导入或测量验证。
- 中间失败：初次类型检查事件数组泛型过窄；初次相关测试4项因事件提交排序失效；初次新场景4项调用了错误的测试组装API。这些已修复，最终日志给出受影响及全量结果。首次完整回归还发现检查脚本注入空字符串数据库变量与原测试要求不符，已改为测试时不设置该变量；品牌入口检查误扫T23测试样本，现只检查产品代码。延迟疼痛反馈已一并写入原安全证据层，补充相应阻断测试后重跑最终完整检查。

## 浏览器继续所需最小操作

将本包的 `source/` 上传到一个新的 Grok 独立 HTTPS 预览，勿替换正式项目；关闭正式数据导入，并把预览链接发回。使用空白测试资料、支持Web Locks的浏览器；收到新URL后才继续真实浏览器验收。不需要提供个人训练数据。
