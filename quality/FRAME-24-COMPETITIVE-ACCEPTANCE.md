# FRAME-24 竞品对照与四周场景验收合同

状态：设计与验收资产已交付；不代表功能实现或测试 PASS。模拟样本，禁止写入真实用户存储。

## 产品定位
聚焦田径专项跑步 + 力量 + 恢复 + 营养 + 多目标，优先验证可靠性而非页面数量。对照 Garmin Connect（设备健康数据）、TrainingPeaks（结构化周期）、Strava（活动回顾）、Fitbod/Hevy（力量记录）。具体竞品功能和版本需在正式评测时复核。

## 四周模拟场景（均为虚构）
| 周 | 训练与输入 | 必须验证 |
|---|---|---|
| W1 | 周二上午力量、晚上 200m×4×2 组；两节各自反馈 | 独立 occurrenceId；保留 rounds/rep/recovery；训练不合并；XP 不重复 |
| W2 | 手表跑步记录缺 HRV、睡眠 5h、RPE 8；次日重复导入 | HRV UNKNOWN；来源与单位清晰；幂等导入；疲劳不自动确诊 |
| W3 | 疼痛反馈、计划调整、休息日；目标为 800m + 力量 + 维持体重 | 风险优先；保留原计划快照；用户确认；休息不扣 XP |
| W4 | 调整周；记录体重、饮食、设备全天消耗；导出后恢复到干净副本 | 不重复累计训练消耗；保留营养/身体历史；备份完整性与恢复差异预览 |

## 逐项验收标准
- 数据：每次训练唯一稳定 ID；同日双训分别保存；重复导入/编辑不重复计数；缺失值不能自动填零。
- 结构：200m×4×2 保留两轮结构及轮间恢复；计划与实际分离；来源可追溯。
- 教练：事实、观察、推断、建议分层；UNKNOWN 不代表安全；伤病风险不作医学诊断；用户可以拒绝建议。
- 营养：全天总消耗与训练消耗不重复相加；缺失能量摄入不能据此判定热量赤字；体脂估算有来源提示。
- 多目标：每个目标有稳定 ID、独立期限和优先级；单次训练只记录一次，可关联多个目标；冲突要解释。
- 数据迁移：完整备份包括训练、身体、营养、目标；导入先验证/预览；不包含 API key/会话令牌；回退路径明确。
- UI：375/390/393/414 px、平板、横屏；不横向溢出；键盘/安全区不遮挡操作；深色与壁纸对比度可读。
- 权益：本地 XP 不作为在线 AI 授权；服务端签发、计数与到期校验；不泄露密钥。

## 验收执行规则
每项记录 PASS/FAIL/NOT_TESTED，附浏览器截图、测试输入、实际输出、代码版本和复现步骤。没有真实运行证据一律 NOT_TESTED。安全/数据丢失类 FAIL 为发布阻断。竞品对比须同样任务同样输入，区分竞品已验证能力与待核查能力。
